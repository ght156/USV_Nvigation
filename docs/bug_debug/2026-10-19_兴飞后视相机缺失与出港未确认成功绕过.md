   `/sensor_health/active_faults` 同时报：

### 3.2 出港

- 船端 `install/arm/usv_docking` 里是旧构建，不含
  `OPEN_LOOP_EXIT_MODES` / `exit_blind_timeout_sec`；旧运动控制器在 `pose` 无效时

  - 13:13:38–13:13:58：`WAIT_DOCK_RELEASE -> UNDOCK_EXIT -> UNDOCK_SETTLE -> IDLE`
  - 13:16:09–13:16:34：同样流程
- 关键日志：

```text
[docking_fsm]: 安全提示: EXIT_POSE_LOST（当前 UNDOCK_EXIT，继续按超时兜底）
[docking_fsm]: UNDOCK_EXIT_UNCONFIRMED：位姿仍无效，按 undock_unconfirmed_as_success=true
               作为人工确认驶出成功（visual_unconfirmed）
[docking_fsm]: 状态: UNDOCK_EXIT -> UNDOCK_SETTLE
```

## 4. 根因

- **后视相机缺失已确证**：USB 设备 `0bda:3035` 不在，`/dev/video*` 不存在，
  导致无图像 → AprilTag 无位姿 → 归港/出港视觉确认不可用。前视相机也同时报故障。
- **出港不动已确证**：`~/usv-test/install/arm/usv_docking` 是旧构建，缺少盲开逻辑；
  旧运动控制器在 `pose` 无效时零速。
- **出港成功判定**：当前用配置参数 `undock_unconfirmed_as_success=true` 把
  “盲开 15 s 位姿仍无效”当作人工确认驶出成功；这是临时绕过，不是相机修复。

## 5. 已做修改

### 5.1 船端 `usv_docking`

- 源文件：
  - `~/usv-test/src/USV_NAV/usv_docking/usv_docking/docking_fsm.py`
  - `~/usv-test/src/USV_NAV/usv_docking/config/docking.yaml`
- 新增参数（源码默认 `false`）：

```yaml
# 相机故障/无位姿盲开 15s 后是否按“人工确认驶出”处理（默认 false）。
# true: 不再报 UNDOCK_EXIT_UNCONFIRMED，而是置 undock_success=true 进
# UNDOCK_SETTLE，让 dock_mission 上报 UNDOCK_SUCCEEDED。
# 仅在后视相机故障、现场目视确认船已驶出坞时临时开启；相机恢复后必须改回 false。
undock_unconfirmed_as_success: false
```

- 船端 **install 配置**临时置 `true`：
  `~/usv-test/install/arm/usv_docking/share/usv_docking/config/docking.yaml`
- 重建（不要用船上的 `make pkgd-r`，见 §5.2）：

```bash
cd ~/usv-test
touch src/USV_NAV/usv_docking/usv_docking/docking_fsm.py   # setuptools 按 mtime 跳过拷贝
source /opt/ros/humble/setup.bash
source install/arm/local_setup.bash
colcon build --build-base build/arm_fix_20261019 --install-base install/arm \
  --base-paths src --packages-select usv_docking \
  --allow-overriding usv_docking --cmake-args -DCMAKE_BUILD_TYPE=Release
```

- 验证：`ros2 param get /docking_fsm undock_unconfirmed_as_success` 返回 `True`；
  两次出港均上报 `UNDOCK_SUCCEEDED` 并收到 ACK。
