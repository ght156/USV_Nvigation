# 船体动力学指标（含测量方法）

> 用途：把"船体/推进系统本身的动态特性"与"软件控制链路的延迟"分开量化，
> 作为 **① 船的性能指标**（换桨/换船/换载后可比对）、**② 归港控制律的设计依据**、
> **③ 出问题时的责任边界依据**（软件链路 vs 船体物理）。
> 本文所有数字都用可复现的试验方法得到，方法见 §2，结论可直接引用。

## 1. 结论速查

| 指标 | 兴飞船（2026-10-07 实测） | 说明 |
|---|---|---|
| **控制链路延迟**（`/cmd_vel_nav` → 速度桥输出） | **0.22 s**（互相关），阶跃 10% @ 0.08s / 90% @ **0.40 s** | 其中 ~0.24s 是速度桥**自身配置的加速度限幅**（`max_angular_accel=0.5 rad/s²`，0.12/0.5=0.24s），可调 |
| **船体响应延迟**（速度桥输出 → IMU 实测角速度） | **1.36 s**（互相关），阶跃 10% @ 0.8~1.3s / 90% @ **1.8~1.9 s** | **船/推进系统的物理特性**，软件侧无法消除 |
| **端到端转向延迟**（`/cmd_vel_nav` → IMU） | **1.58 s** | = 0.22 + 1.36，两段可加，数据自洽 |
| 转向角速度上限 | **⚠️ 两个数不一致，待定值**：0.13 rad/s（2026-07-29 归港侧实测：cmd 0.35 也只到 0.135）／ 0.25 rad/s（2026-10-05 导航侧水测，见 `nav2_params_xingfei.yaml` 注释） | 差速双推进、船体转动惯量大。**2026-10-07 的阶跃试验测不到上限**（只发 ±0.12），须用**阶梯递增**（0.10→0.15→0.20→0.25→0.30→0.35，各 3~5 s）重测 |
| 船体 footprint（长） | **≈2.7 m**（船头在 base_link 前方约 2.8 m，含 padding） | 2026-10-07 从 `nav2_params` 注释确认；**间隙/角度换算必须按此**（早先按 1.6 m 估算的表已作废） |
| 原地旋转的"最小可达对齐带" | **≈ ω × 1.36 s**（例：0.12 rad/s → ~10°） | 由上面的响应滞后决定：**任何"原地转到某个角度再停"的阈值都不能小于这个量级**，否则必然转过头 → 误差反号 → 左右摆（2026-10-07 两侧都实测到：归港 APPROACH 摆头、Nav2 RPP `rotate_to_heading_min_angle=0` 时 v≡0 只摆） |
| 线速度能力 | 倒退实测 -0.45 → 0.47 m/s，前进/倒退基本对称 | 线速度不是瓶颈 |
| 加速能力 | `max_linear_accel` 0.30 / `max_angular_accel` 0.50（软件限幅值） | 限幅是"软"的，可调；船体本身另有惯量上限 |

**一句话**：**归港里所有"转角慢、来回摆"的问题，根子在 1.36 s 的船体响应延迟**，
而软件链路（控制器 → 速度桥）只占 0.22 s 且其中大部分是可调的加速度限幅。

## 2. 测量方法（可复现）

### 2.1 转向阶跃试验（本文数据来源）

**前置条件**（安全）：飞控 `GUIDED` + `armed`；归港 FSM 处于 `IDLE`（控制器静默，
`/cmd_vel_nav` 无人发布）；开阔水域、有人持遥控器。

```bash
# 船上：录制（脚本需含下列话题）
~/record_dock_data.sh start turnstep

# 船上：发方波（脚本：w=±0.12 rad/s，2s 换向，5 个周期，首尾各 2s 零速）
python3 scripts/dock_test/cmd_step.py        # 参数：振幅 半周期 周期数

# 停录 + 分析（互相关 + 阶跃响应）
~/record_dock_data.sh stop
python3 scripts/dock_test/an_step.py ~/usv_bags/dock_*_turnstep
```

**需要录的话题**（四个信号构成一条链）：

| 话题 | 含义 |
|---|---|
| `/cmd_vel_nav` | 控制器输出（链路的输入） |
| `/mavros/setpoint_velocity/cmd_vel_unstamped` | 速度桥的输出（发给飞控） |
| `/mavros/rc/out` | 飞控执行器 PWM 输出（把"飞控+链路"与"推进器+船体"分开的关键） |
| `/mavros/imu/data` | 船体实际角速度（物理输出） |

**处理**：四路信号重采样到 50 Hz（保持量），两两做互相关取峰值延迟（正=后段滞后），
并对 `cmd_vel_nav` 的跳变沿做阶跃响应（10% / 90% 到达时间）。

### 2.2 已知的测量限制（下次可改进）

- **`/mavros/rc/out` 目前录不到**：船上 `mavros_msgs` 缺 Python 绑定，`ros2 bag record`
  报 `unknown type 'mavros_msgs/msg/RCOut'`（`ros2 interface show` 能看定义是因为它只读 .msg）。
  → **装上 `ros-humble-mavros-msgs`（或重建 mavros_msgs）后**，就能把上面的 1.36 s
  再拆成「MAVROS 链路+飞控」与「推进器+船体」两段；
- 因此 **1.36 s 内部的比例目前是推断**（链路是同局域网 UDP、飞控内环 ≥50 Hz，
  推断飞控+链路只占几十毫秒，其余是推进器起转 + 船体惯量），**待 rc/out 补齐后坐实**。

- 船：兴飞（`ssh hkzl`，MEC-MB002），ROS_DOMAIN_ID=5 / cyclonedds
- 工况：湖面平静、开阔水域、无负载变化
- 输入：`/cmd_vel_nav` 上 `w = ±0.12 rad/s` 方波，半周期 2 s，5 个周期（共 20 s）
- 数据：`~/usv_bags/dock_20261007_172108_turnstep`（194 MB）

## 4. 对控制律的直接含义

| 现象 | 归因 | 可做的事 |
|---|---|---|
| 转角慢、修艏偏要 8~15 s | 船体 1.36 s 延迟 + 角速度上限（0.13~0.25 待定） | 只能"提前量"：**调大 `kd_yaw`**（IMU 实测角速度阻尼，2026-10-07 起 0.7）；把转动任务**提前**到坞外完成（`align_*` 阶段）；**降增益离开饱和区**（kyaw 常打满 0.12） |
| APPROACH/BACK_IN 来回摆头 | 上述延迟 + 纯 P 律在饱和区 | 同上；必要时对 `e_yaw` 做超前补偿 |
| 线速度足够但入坞仍慢 | 不是线速度问题 | 别调速度参数，调"转角/对准"环节 |
| **Nav2 里"原地转到某个角度再走"阈值设得太小 → 一步不走/左右摆** | 同上：阈值 < 最小可达对齐带 ≈ ω×1.36 s | 2026-10-07 实测：RPP `rotate_to_heading_min_angle=0` ⇒ `v≡0`、`w` 在 ±0.25 摆 215 s。阈值不得小于该对齐带（详见 `docs/bug_debug/2026-10-07_Nav2导航不动-…md`） |

**推论（责任边界）**：归港"转角慢/来回摆"的**主因是船体特性**（1.36 s），
软件链路仅 0.22 s 且大部分是可调的加速度限幅——因此这类问题**不应通过改控制律"消除"，
只能补偿**；真正的软件缺陷应表现为"指令本身错了"（如假横偏、锚点被搬走），
那类问题的证据形态完全不同（`/dock/status` 里的 `e_y/x` 会突变，而本试验的链路各段相关度正常）。

> 2026-10-07 补充：这条"船体滞后"还解释了两个**看起来像软件 bug** 的现象——
> ① 归港 APPROACH 段长时间原地摆头（§上文）；② Nav2 导航"只转不走"。
> 两者的调参共性：**任何"转到阈值内再动作"的设计，阈值都必须 ≥ 最小可达对齐带**。
