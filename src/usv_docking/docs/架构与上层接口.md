# 归港四节点管线：架构、状态机与上层接口说明

> 适用代码：`usv_docking/docking_*.py`（四节点管线）+ `config/docking.yaml`。
> 旧系统（`docking_controller.py`，v4/v5）已于 2026-08-31 移除。

---

## 1. 系统定位

本包负责 **预泊点之后 → 坞内充电位** 的最后几米精靠泊，以及 **出泊驶离**。

- **全程船尾朝坞**（倒船入坞）：船尾装有无线充电接收端与后相机，后相机必须全程盯住坞内 AprilTag。
- **不做长距离导航**：从任意位置到预泊点由 Nav2 / `dock_mission` 负责（见 `../dock_mission/README.md`）。
- 输出仅为 `cmd_vel`（差速双推进：`linear.x` + `angular.z`），由既有 `converter` 映射到推进器；本包无独立推力分配节点。

## 2. 四节点管线与数据流

```text
AprilTag TF (camera_rear_link→dock_frame，仅检测到 Tag 时发布) + odom→base_link TF (EKF)
  │
  ▼
docking_pose_estimator          # 位姿估计
  │  · 见 Tag：计算 odom→dock_est 锚点，EMA 滤波 + 跳变拒绝
  │  · 丢 Tag：闩锁锚点，用当前 odom 推算船在坞系位姿（≤70s 硬上限）
  │  · 广播 TF: odom→dock_est
  │  发布:
  │    /docking/dock_pose        (PoseStamped) base_link 在 dock_est 系位姿
  │    /docking/tag_visible      (Bool)
  │    /docking/pose_source      (String: VISION / ODOM_PREDICTION / INVALID)
  │    /docking/measurement_age  (Float32, 距上次真实测量的秒数)
  ▼
docking_fsm                     # 状态机（10Hz）
  │  订阅: 上述 4 话题 + /docking/abort_request
  │       + /dock/start + /dock/cancel + /dock/undock  (上层指令)
  │  发布:
  │    /docking/state            (String) 当前状态
  │    /docking/target_mode      (String) 下发给控制器的阶段目标模式
  │    /docking/reset_anchor     (Bool) 进 ACQUIRE 时重置锚点
  │    /dock/status                 (String JSON) 对上层唯一契约，见 §6
  ▼
docking_motion_controller       # 运动控制（按 target_mode 选控制律）
  │  订阅: /docking/{target_mode, dock_pose, pose_source, safety_stop}
  │  发布: /cmd_vel_nav             (test_only:=false，真实接管)
  │        /docking/cmd_vel_test (test_only:=true，观察模式)
  ▼
converter → 推进器

docking_safety                  # 独立安全监督（旁路，不在数据流主链上）
  │  订阅: 估计器/FSM 全部状态话题
  │  发布:
  │    /docking/safety_stop      (Bool) 控制器立即零速（硬停）
  │    /docking/abort_request    (String) 请求 FSM 裁决撤离（软停）
```

**设计要点**：估计 / 决策 / 控制 / 安全四者解耦，可单节点替换；安全监督独立成节点，即使 FSM 卡死也能硬停。

## 3. 坐标系约定

| 坐标系 | 说明 |
|--------|------|
| `dock_frame` | apriltag 输出，原点在坞中心，**仅在检测到 Tag 时发布**（间歇性） |
| `dock_est` | 估计器锚定出的坞系（`odom→dock_est` 持续广播）。**+x 从入口指向坞内**（坞外 x<0，坞中心 x=0），+y 侧向 |
| `base_link` | 船体；对准 = 艏向 ±π（船尾朝坞），`e_yaw = wrap(yaw − π)` 收敛到 0 |
| `dock_pose` 语义 | x：船在坞轴上的位置（坞外为负，倒入时向 0 收敛）；y：横向偏差（轴线为 0）；e_yaw：艏向偏差 |

## 4. 状态机（docking_fsm）

### 4.1 正常链路

```text
IDLE → [WAIT_DOCK_OPEN*] → ACQUIRE_TAG → APPROACH_ENTRY → ALIGN_ENTRY → BACK_IN → FINAL_DOCK → DOCKED
* 船坞夹爪交互状态，仅 dock_claw_enabled=true（默认 false）时启用
```

| 状态 | 行为（target_mode） | 转移条件 | 超时 |
|------|--------------------|----------|------|
| `IDLE` | 零速（HOLD） | `/dock/start` → ACQUIRE_TAG（夹爪模式 → WAIT_DOCK_OPEN）；`/dock/undock` → UNDOCK_EXIT（夹爪模式 → WAIT_DOCK_RELEASE） | — |
| `WAIT_DOCK_OPEN`（夹爪模式） | 零速（HOLD）；请求船坞打开夹爪（usv_rs485_driver ControlDO action） | ControlDO 成功 → ACQUIRE_TAG；失败 → IDLE + needs_reapproach | dock_open_timeout_sec(15s) → IDLE + needs_reapproach |
| `ACQUIRE_TAG` | 无锚点：原地旋转搜索（SEARCH）；见 Tag：停车集帧（HOLD，连续 N=5 帧 VISION 才锚定） | 锚定成功 → 按位姿路由（坞边/已过点 → BACK_IN 或 APPROACH；否则 APPROACH_ENTRY） | 60s → 失败回 IDLE |
| `APPROACH_ENTRY` | 双向就位（APPROACH）：船在预备点外侧→倒退入位；内侧（过冲/坞边重启）→前进倒出，蟹行角限幅 8° | 到达预备点（\|x−(−2.5)\|≤0.4 且 \|y\|≤0.15）→ ALIGN_ENTRY | 120s → 失败回 IDLE |
| `ALIGN_ENTRY` | 小倒速弧线对准（ALIGN，v=−align_arc_speed，x 超 align_arc_x_limit 回退 v=0；只修 e_yaw） | \|e_yaw\|≤5° 且 \|y\|≤0.15 持续 1s → BACK_IN；**艏向已准但 y 滞留 (0.15, 0.35] 超 6s → 回 APPROACH 修 y**（卡死带确定性逃逸） | 45s → 失败回 IDLE |
| `BACK_IN` | 沿轴线倒入（BACK_IN，门控分级速度）；夹爪模式：发 WaitIO 等夹爪抓住，抓住即 DOCKED | \|x−final_target_x\|<0.8 且 \|y\|≤final_dock_entry_y_tol(0.15) → FINAL_DOCK | 90s → ABORT_EXIT；夹爪模式位移停滞 backin_stuck_timeout_sec(15s) → ABORT_EXIT（`BACK_IN_STUCK`） |
| `FINAL_DOCK` | 低速倒向充电位（FINAL_DOCK）；x 达位但 \|y\|>docked_y_tol 时保持小倒速让横向律有行程（行程以 docked 窗口远缘为界）；x/y 达标后原地消艏偏 | \|x\|≤0.15 且 \|y\|≤0.10 且 \|e_yaw\|≤3° 持续 → DOCKED（**夹爪模式下位置判据停用**，改由 WaitIO 抓住 → DOCKED；位移停滞 → ABORT_EXIT `FINAL_DOCK_STUCK`） | → ABORT_EXIT |
| `DOCKED` | 零速保持（DOCKED_HOLD），`success=true` | `/dock/undock` → UNDOCK_EXIT；`/dock/cancel` → IDLE | — |

### 4.2 异常状态

```text
入口外丢 Tag ──► REACQUIRE_TAG ──(重捕获)──► 路由回原状态
坞内失败     ──► ABORT_EXIT ──(驶出到位 / 超时且位姿有效)──► IDLE + needs_reapproach
                          └──(超时且位姿 INVALID)──► IDLE + ABORT_EXIT_UNCONFIRMED
                             （needs_reapproach=false，不盲重试，待人工/上层裁决）
```

| 状态 | 触发 | 行为 | 结束 |
|------|------|------|------|
| `REACQUIRE_TAG` | 入口外状态（ACQUIRE/APPROACH/ALIGN）中 `pose_source=INVALID`，或 ALIGN 丢 Tag 超宽限（5s） | 无锚点：SEARCH 扇形搜索；**看到 Tag 立即停车集帧**（HOLD，同 ACQUIRE，防边转边锚定不收敛） | 集帧 5 帧 → 按当前位姿路由回 APPROACH/ALIGN/BACK_IN；60s → 失败 |
| `ABORT_EXIT` | 坞内状态（BACK_IN/FINAL_DOCK）失败、safety 请求、坞内丢 Tag>2s | EXIT_FORWARD：沿坞轴**前进驶出**（船尾相机仍朝坞），全靠 odom 推算（故估计器推算上限 70s > 撤离窗口 60s）；位姿 INVALID 时控制器只能停车 | 驶出到位/超时（位姿有效）→ IDLE + `needs_reapproach=true`；超时且位姿 INVALID → IDLE + `abort_reason=ABORT_EXIT_UNCONFIRMED`、`needs_reapproach=false`、`needs_manual_takeover=true` |
| `FAILED` | 安全硬失败（ODOM*/TOPIC_TIMEOUT）、出泊超时 | 零速，等待上层裁决 | `/dock/cancel` → IDLE；`/dock/start` 重新开始 |

**关键分工**：本包内部**不自动重试**。入泊失败统一回 IDLE/FAILED 并置 `needs_reapproach=true`，重 Nav 预泊→再试的决策由 `dock_mission` 做。

### 4.3 出泊链路

```text
DOCKED/IDLE ──/dock/undock──► [WAIT_DOCK_RELEASE*] ──► UNDOCK_EXIT ──► UNDOCK_SETTLE ──► IDLE (undock_success=true)
* 夹爪模式（dock_claw_enabled=true）：先请求船坞松开夹爪（ControlDO）
```

- `WAIT_DOCK_RELEASE`（夹爪模式）：零速等待 ControlDO 结果；成功 → UNDOCK_EXIT；失败/超时（dock_open_timeout_sec）→ FAILED（`DOCK_RELEASE_FAILED`/`DOCK_RELEASE_TIMEOUT`，爪子可能仍扣着，禁止盲动，需人工处置）。

- `UNDOCK_EXIT`：UNDOCK_FORWARD 沿轴前进驶出至安全距离（默认出坞 2.5m+），纯 odom 推算兜底；60s 超时 → FAILED（`undock_success=false`）。
- `UNDOCK_SETTLE`：停车稳定后上报 `undock_success=true`。

### 4.4 坞内丢 Tag 分级（BACK_IN/FINAL_DOCK 专属）

| 丢失时长 | BACK_IN 行为 | FINAL_DOCK 行为 |
|---------|-------------|-----------------|
| 0 ~ 0.5s | 停车等待（HOLD） | 停车等待 |
| 0.5 ~ 2s | 小角度搜索（SEARCH_LIMITED，±8°） | 只等待不搜索 |
| > 2s | ABORT_EXIT | ABORT_EXIT |

### 4.5 target_mode 一览

| mode | 含义 | 典型线速度 |
|------|------|-----------|
| `HOLD` | 零速 | 0 |
| `SEARCH` | 旋转/扇形搜索（无位姿时开环，有推算时闭环指向预测坞方位） | v=0，ω≤0.35 |
| `APPROACH` | 双向就位（倒退入位 / 前进倒出，蟹行限幅 8°） | ≤0.45 |
| `ALIGN` | 小倒速弧线对准（x 超 align_arc_x_limit 回退 v=0 纯旋转） | ≤align_arc_speed(0.08) |
| `BACK_IN` | 倒入（门控：误差小 0.40 / 中 0.20 / 大 v=0 原地修艏向） | ≤0.40 |
| `FINAL_DOCK` | 低速倒入充电位 + 终局消艏偏 | ≤0.15 |
| `SEARCH_LIMITED` | 坞内小角度搜索 | v=0 |
| `EXIT_FORWARD` / `UNDOCK_FORWARD` | 前进驶出 | ≤0.30 |
| `DOCKED_HOLD` | 入泊保持 | 0 |

> 2026-09-01：`HOLD`/`DOCKED_HOLD` 停稳且持续发零速满 `hold_zero_publish_sec`(1.0s)
> 后控制器**静默**（不再占用 `/cmd_vel_nav`，teleop 可直接接管；实船
> `usv_ardupilot_velocity_bridge` 有 `command_timeout_sec` 看门狗超时自动清零）。
> 运动态（含位姿不可用停车）仍常发。同时修复：回 IDLE 清 `success` 残留
> （否则二次归港假成功被 cancel 掐掉）；`FAILED` 接受 `/dock/start` 重新开始。

## 5. 安全监督（docking_safety，6 项检查）

| # | 检查 | 阈值（yaml） | 动作 | 适用范围 |
|---|------|-------------|------|---------|
| 1 | 纵向误差 \|x\| | max_longitudinal_error | abort_request | 坞内状态 |
| 2 | 横向误差 \|y\| | max_lateral_error | abort_request | **仅 BACK_IN/FINAL_DOCK**（开阔水域/搜索态不查，防远距离噪声误杀） |
| 3 | odom 推算超时 | 3s；**ALIGN_ENTRY 独立窗口 align_odom_prediction_timeout=7s**（须 > FSM align 丢 Tag 宽限 5s，否则抢跑 ODOM_TIMEOUT 使 REACQUIRE 走不到）；撤离通道 60s | abort_request | **豁免 ACQUIRE/REACQUIRE**（搜索本就靠长时推算）；撤离通道位姿 INVALID 持续 exit_pose_invalid_warn_sec(5s) 发提示性告警 `EXIT_POSE_LOST`（FSM 仅记录不改状态） |
| 4 | tag 数据龄期 | tag_max_age | safety_stop | 有视觉依赖的状态 |
| 5 | 艏向误差 | max_yaw_error | abort_request | 坞内状态 |
| 6 | 走廊违规（BACK_IN gate2 超限持续 N 周期） | back_in_gate2_* × violation_cycles=10 | abort_request → ABORT_EXIT | BACK_IN/FINAL_DOCK |

- `safety_stop`（Bool）：控制器**立即零速**（硬停，不等 FSM 裁决）。
- `abort_request`（String，原因码如 `SAFETY:LATERAL_ERROR`）：FSM 裁决——坞内 → ABORT_EXIT；坞外 → 失败回 IDLE。

## 6. 与上层对接契约

### 6.1 两级触发链路

```text
GCS / 地面站                              dock_mission（任务编排）           usv_docking
────────────────────────────────────      ──────────────────────────────      ──────────────
topic /gcs_dock/command (JSON)            Nav2 送到预泊点 → Entry 验收
  action: 一键归港/仅归港段/出泊/取消         │
或 topic /dock/home (Bool, =一键归港)        ├─► /dock/start  (Bool) ──────► 开始靠泊
或 service /dock/mission/start (Trigger)   ├─► /dock/undock (Bool) ──────► 出泊
                                           └─► /dock/cancel (Empty) ─────► 取消回 IDLE
                                            ◄──── /dock/status (String JSON) ── 状态反馈
```

> 注意：对 **usv_docking** 而言三个触发都是 **topic**（不是 service），由 dock_mission 转发；`/dock_task/command` service 已移除（`DockTaskCommand.srv` 2026-07-28 从 m_common 删除）。手动调试时可绕过 dock_mission 直接发话题（见 README 分步命令）。

### 6.2 上层 → 本包（订阅）

| 话题 | 类型 | 语义 | 备注 |
|------|------|------|------|
| `/dock/start` | `std_msgs/Bool` | 开始靠泊（IDLE/FAILED → ACQUIRE_TAG） | **Bool 不是 String**，`data: true` |
| `/dock/cancel` | `std_msgs/Empty` | 取消：任何状态 → IDLE，零速 | ABORT_EXIT 中也生效（立即接管） |
| `/dock/undock` | `std_msgs/Bool` | 出泊（DOCKED/IDLE → UNDOCK_EXIT） | |

### 6.3 本包 → 上层：`/dock/status`（String JSON，dock_mission 唯一消费）

| 字段 | 类型 | 说明 |
|------|------|------|
| `state` | string | 对上层的状态名。**FAILED 映射为 `"DOCK_ABORT"`**（兼容旧契约），真实状态见 `v2_state` |
| `v2_state` | string | 真实状态名（§4 全部状态） |
| `target_mode` | string | 当前下发给控制器的模式（§4.5） |
| `success` | bool | **入泊成功**（DOCKED 置 true），dock_mission MONITOR_DOCK 据此判完成 |
| `undock_success` | bool | **出泊成功**，dock_mission MONITOR_UNDOCK 据此判完成 |
| `needs_reapproach` | bool | 入泊失败需重新接近；**FAILED 时强制 true**（防上层挂死） |
| `needs_manual_takeover` | bool | 需人工接管 |
| `abort_reason` | string | 失败/撤离原因码（如 `SAFETY:LATERAL_ERROR`、`CORRIDOR_VIOLATION`、`UNDOCK_TIMEOUT`、`ABORT_EXIT_UNCONFIRMED`；夹爪模式新增 `DOCK_OPEN_FAILED/TIMEOUT`、`DOCK_RELEASE_FAILED/TIMEOUT`、`BACK_IN_STUCK`、`FINAL_DOCK_STUCK`、`WAIT_IO_FAILED`） |
| `pose_valid` | bool | `pose_source != INVALID` |
| `pose_source` | string | `VISION` / `ODOM_PREDICTION` / `INVALID` |
| `tag_visible` | bool | Tag 是否在视野 |
| `tag_age_sec` | float/null | 距上次真实测量秒数（Infinity 时为 null） |
| `mission_elapsed_sec` | float | 本次任务耗时 |
| `dock_claw_enabled` | bool | 夹爪交互是否开启（参数） |
| `claw_grabbed` | bool | 夹爪是否已抓住（WaitIO 结果） |
| `dock_x` / `dock_y` | float | 船在坞系位置（m） |
| `e_yaw_deg` | float | 艏向偏差（°） |

**上层判据速查**：
- 入泊完成：`success == true`
- 入泊失败可重试：`needs_reapproach == true`（dock_mission 应重 Nav 预泊后再 `/dock/start`）
- 驶出未确认：`abort_reason == "ABORT_EXIT_UNCONFIRMED"`（ABORT_EXIT 超时且位姿 INVALID；`needs_reapproach=false`，dock_mission 不会自动重试，需人工接管或 `/dock/cancel` 后处置）
- 出泊完成：`undock_success == true`
- 任意异常：看 `abort_reason` + `v2_state`

## 8. 参数治理原则（真船前必读）

全部参数集中在 `config/docking.yaml`，注释含符号推导与历次实测缺陷记录。真船阶段必须按实际船型/坞尺寸复核：

1. **坞宽≈船宽**：y 必须在坞外修到位（`align_y_tol`），BACK_IN 门控（`back_in_gate1_y/gate2_y`）仅兜漂移——按 **单侧间隙 − 安全余量** 收紧。
2. **撤离链路**：`odom_prediction_timeout`(70s) 必须 ≥ safety 撤离窗口(60s)，否则 ABORT_EXIT 中途瘫痪。
3. **速度/加速度**：当前值针对仿真 RTF≈0.1 放大过（约 2 倍），真船务必按实际动力学校准。
4. `staging_x` / `final_target_x` 按实际坞尺寸与充电位设置。
