## 0. 两套启动命令（按功能顺序起，照抄即可）

### 0.1 RTK / GNSS 定位（默认）

```bash
# ① 志昂定位（map→odom + base_link→传感器）
ros2 launch usv_localization usv_map_odom_tf.launch.py publish_robot_tf:=true map_config_yaml:=$HOME/usv-main/app/map/map.yaml

# ② 导航
ros2 launch workspace_nav nav2_boat.launch.py params_file:=$HOME/usv-main/src/USV_NAV/workspace_nav/config/nav2_params_xingfei.yaml map:=$HOME/usv-main/app/map/map.yaml enable_mission_bridge:=true

# ③ 速度桥
ros2 launch usv_ardupilot_velocity_bridge ardupilot_velocity_bridge_xingfei.launch.py

# ④ 归港
ros2 launch usv_docking docking.launch.py test_only:=false
ros2 launch dock_mission dock_mission.launch.py

# ⑤ 激光雷达
ros2 launch livox_ros_driver2 msg_MID360s_launch.py
```

### 0.2 SLAM 定位（lightning LIO）

```bash
# ① 先让 MAVROS 交出 odom→base_link（SLAM 接管；不交会两处抢同一段 TF）
ros2 param set /mavros/local_position tf.send false

# ② SLAM 定位（LIO + RTK 后端 + nav bridge + base_link→传感器 TF）
ros2 launch lightning run_lightning_odom.launch.py map_yaml:=$HOME/usv-main/app/map/map.yaml use_robot_tf:=true
# 船端一键等价： ~/USV/usv/usv-main/scripts/start_odom.sh --no-prereq map_yaml:=$HOME/usv-main/app/map/map.yaml
# ⚠️ 这一套里【不要】再起志昂定位（usv_map_odom_tf），它会和 SLAM 抢 map→odom

# ③ 导航（mission 栈由 nav2_boat 一体拉起；odom_topic 会自动透传给 mission 栈，不用单独起 mission_bridge）
ros2 launch workspace_nav nav2_boat.launch.py params_file:=$HOME/usv-main/src/USV_NAV/workspace_nav/config/nav2_params_xingfei.yaml map:=$HOME/usv-main/app/map/map.yaml enable_mission_bridge:=true odom_topic:=/slam/localization

# ④ 速度桥（与 RTK 版相同，与定位源无关）
ros2 launch usv_ardupilot_velocity_bridge ardupilot_velocity_bridge_xingfei.launch.py

# ⑤ 归港（带 odom_topic）
ros2 launch usv_docking docking.launch.py test_only:=false odom_topic:=/slam/localization
ros2 launch dock_mission dock_mission.launch.py

# ⑥ 激光雷达（与 RTK 版相同）
ros2 launch livox_ros_driver2 msg_MID360s_launch.py
```

### 0.3 两版差异（只有这三处）

| | RTK/GNSS 版 | SLAM 版 |
|---|---|---|
| 定位 | `usv_localization usv_map_odom_tf.launch.py`（map→odom），`odom→base_link` 由 MAVROS 发 | `lightning run_lightning_odom.launch.py`（两段 TF 都归它），**另加** `ros2 param set /mavros/local_position tf.send false` |
| 导航 | `nav2_boat.launch.py`（`enable_mission_bridge:=true` 一并拉起 mission 栈），不传 `odom_topic`（用 yaml 里的 `/mavros/gps_input/local`） | 同上，但 `nav2_boat.launch.py` 传 `odom_topic:=/slam/localization`（自动覆盖 Nav2 三处 + 透传 mission 栈三节点） |
| 归港 | 不传 `odom_topic` | `docking.launch.py` 传 `odom_topic:=/slam/localization` |

> 两条补充：
> - **感知（AprilTag）不在本清单里**：归港末端靠视觉，按现有部署另起 `ros2 launch perception_launch cleaning_boat_xingfei.launch.py`（jzw_ws）。
> - **不要再单独起 `mission_bridge.launch.py`**：mission 栈已由 `nav2_boat.launch.py` 拉起，两边同时起会出现同名节点。若确有需要单独起，必须显式补 `map_yaml_path:=$MAP` 和 `odom_topic:=...`——它默认取包内 `workspace_nav/config/map.yaml`，与 Nav2 用的 app/map 不是同一张图。

## 2. 定位源台账（改哪几个开关）

| 定位源 | `map→odom` 谁发 | `odom→base_link` 谁发 | `base_link→传感器` 谁发 | odom 话题 |
|---|---|---|---|---|
| **RTK/GNSS**（默认） | 志昂定位 `usv_map_odom_tf`（读 `map.yaml` 锚点 + GI320 RTK，启动时锁定一次） | MAVROS `local_position`（`tf.send=true`） | `usv_map_odom_tf.launch.py` 的 `publish_robot_tf:=true` | `/mavros/gps_input/local` |
| **SLAM** | `run_rtk_pgo` / `slam_nav_bridge` | `run_slam_online`(LIO) / `slam_nav_bridge` | SLAM 栈 `use_robot_tf:=true` | `/slam/localization` |
| **视觉 AprilTag** | 不参与 map 系 | — | — | 坞内 `base_link→dock_frame`，归港估计器内部用，**不是**可切换的定位源 |

三条铁律：

1. **同一段 TF 只能有一个发布者**（`map→odom`、`odom→base_link`、`base_link→传感器` 各一处）。
2. **odom 话题三处同源**：Nav2（`bt_navigator`/`controller_server`/`velocity_smoother`）、mission 栈（`mission_bridge`/`nav_status_aggregator`/`zone_monitor`）、归港（`docking_fsm`）。
3. **地图三处同源**：Nav2 `map:=` ↔ 定位 `map_config_yaml:=` / SLAM `map_yaml:=` ↔ mission `map_yaml_path:=`。

## 3. 启动顺序与自检

顺序：**感知/定位 → 导航 → 速度桥 → 归港**（速度桥要在归港之前，否则归港发的 `/cmd_vel_nav` 无人消费；激光雷达服务于避障，随栈起即可）。

```bash
# 频率
ros2 topic hz /mavros/gps_input/local        # RTK 版；SLAM 版换成 /slam/localization（期望 ≥20 Hz）
ros2 topic hz /livox/lidar                   # 避障观测源
ros2 topic hz /docking/tag_visible           # 视觉链

# TF：两段都要能解，无 "two or more unconnected trees"
ros2 run tf2_ros tf2_echo map base_link
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link camera_back_video_link
ros2 run tf2_ros tf2_echo base_link dock_frame
ros2 param get /mavros/local_position tf.send      # SLAM 版期望 False

# 节点/状态
ros2 node list | grep -E 'map_server|controller_server|bt_navigator|docking_|dock_mission|usv_map_odom_tf|slam'
ros2 topic echo --once /docking/state         # 期望 IDLE
ros2 topic echo --once /docking/pose_source   # tag 可见时期望 VISION
ros2 topic echo --once /nav_status            # localization 不应 DEGRADED

# 录制（每次实船归港必开）
./scripts/record_dock_data.sh start <标签>     # 船端：~/record_dock_data.sh
```

归港成功判据（2026-10-05 起）：FINAL_DOCK → 压紧段低速续倒 → 无线充电 `charging_status∈{1,5}` 稳定 2s，或 WaitIO 夹爪 DI(0x0003) 先到 → `DOCKED`。

## 4. 只跑归港栈（不启 Nav2）

船由人遥控摆到坞轴线（坞外 5~10 m、船尾朝坞）时，只起 §0 里的**定位 + 速度桥 + 归港**三段（不跑 `nav2_boat` / `mission_bridge`）：

```bash
ros2 topic pub --once /dock/start std_msgs/msg/Bool '{data: true}'                                 # 触发精靠泊
ros2 topic pub --once /gcs_dock/command std_msgs/msg/String '{data: "{\"action\": \"undock\"}"}'    # 出泊
```

船端一键（速度桥 + usv_docking 四节点 + dock_mission）：

```bash
ssh nx '~/start_dock_stack.sh start'    # 日志 ~/logs/dock_stack/
ssh nx '~/start_dock_stack.sh status'
```

取消（`dock_mission` 的取消不撤 Nav2 目标，必须一起发）：

```bash
ros2 service call /dock/mission/cancel std_srvs/srv/Trigger
ros2 topic pub --once /dock/cancel std_msgs/msg/Empty
ros2 service call /mission_bridge/cancel_mission std_srvs/srv/Trigger
```

Nav2 + mission_bridge 也在跑时，正式入口是 `/gcs_dock/command`（按 [`归港任务对接文档.md`](归港任务对接文档.md) 填 `action` 与可选预泊点），另有 `/dock/mission/start`（`std_srvs/Trigger`）与等价的 `/dock/home`（`std_msgs/Bool`）。

## 6. 常见坑

| 现象 | 根因 | 处置 |
|---|---|---|
| RViz 里船跳/起振 | `map→odom` 或 `odom→base_link` 有**两个**发布者（典型：SLAM 版忘了关 MAVROS `tf.send`，或没关志昂定位） | 按 §2 台账只留一个；`ros2 topic info /tf -v` 看发布者 |
| 归港 `pose_source` 一直 `INVALID`（tag 却检得到） | 缺 `base_link→camera_back_video_link`（`publish_robot_tf:=false`，或两处抢 TF） | `tf2_echo` 先验证；保持 `publish_robot_tf:=true` |
| 导航能规划但船不动 | 行为树缺 `goal_checker_id`（`FollowPath` 空 checker 立即 abort） | 用本仓 `nav2_boat.launch.py`（已注入 `navigate_to_pose_w_goal_checker.xml`），别用官方 bringup |
| 位置整体偏出地图 | Nav2 `map:=` / 定位 `map_config_yaml:=` / mission `map_yaml_path:=` 指向了不同的图 | 三处都传 `$HOME/usv-main/app/map/map.yaml` |
| 切 SLAM 后 mission 栈判定位异常 | `mission_stack` yaml 里 `odom_topic` 写死 MAVROS，只改了 Nav2 侧 | 走 §0.2：`nav2_boat.launch.py odom_topic:=/slam/localization` 会自动透传给 mission 栈三节点；单独起 mission 时才需手动传 |
| 同名节点两份（服务/话题时好时坏） | mission 栈同时被 `nav2_boat.launch.py enable_mission_bridge:=true` 和单独的 `mission_bridge.launch.py` 拉起 | 二选一：用一体启动就别再单独起 |
| 改 costmap 观测源参数"没效果" | 观测源级参数（`obstacle_max_range`/`marking`/`clearing`）在线改是 phantom | 改 yaml + `~/start_xingfei_stack.sh stop/start` |
| 节点残留 / modbus 冲突 / service 丢响应 | 上次 `ros2 launch` 父进程死后子进程不退 | 一律走栈脚本 `stop`→`start`；排查先 `pgrep -af` |
| 改完 `usv_localization` 不生效 | 船端是拷贝安装（`install/arm`） | `colcon build --install-base install/arm --packages-select usv_localization` |
| `usv_map_odom_tf` 报 xacro 打不开（附带 `AttributeError: module 'xml' has no attribute 'parsers'`） | 默认 xacro 是旧路径，船上不存在 | 补 `robot_description_file:=$HOME/usv-main/src/usv_transforms/urdf/cleaning_boat_xingfei.xacro` |

## 8. 附录：`mission_stack.*.yaml` 是什么（只按定位源区分，不按船）

Nav2 侧有**两族**参数文件，分工不同、不要混：

| 文件 | 给谁用 | 典型内容 |
|---|---|---|
| `nav2_params_xingfei.yaml` | **Nav2 本体**（`bt_navigator` / `controller_server` / `planner_server` / costmap / `velocity_smoother`） | 船体 footprint、RPP lookahead、限速与加速度、costmap 观测源、`odom_topic` |
| `mission_stack.chengfeng.yaml` | **mission 栈四个节点**：`mission_bridge`、`nav_status_aggregator`、`zone_manager`、`zone_monitor` | 上层任务接口（航点容差、取消话题）、`/nav_status` 上报（`vehicle_id`、`odom_timeout`、`min_odom_hz`）、电子围栏 |

`mission_stack` 这族文件**只按定位源区分，不按船区分**：同一份参数两条船通用，唯一与定位源绑定的是三处 `odom_topic`（`mission_bridge` / `nav_status_aggregator` / `zone_monitor` 各一处）。所以**不按船命名副本**（没有也不需要 `mission_stack.xingfei.yaml` 这种名字）；现有文件名里的 `chengfeng` 是早期按船命名留下的，内容本身与船无关。

换定位源两种做法，二选一：

| 做法 | 怎么用 | 说明 |
|---|---|---|
| **A. 一份文件 + launch 覆盖**（推荐，现在就这么用） | 见 §0.2：`nav2_boat.launch.py enable_mission_bridge:=true odom_topic:=/slam/localization`，自动覆盖 Nav2 三处并透传给 mission 栈三节点 | 不动文件，三处一起改，最不容易漏 |
| **B. 按定位源存两份** | 复制成 `mission_stack.mavros.yaml` / `mission_stack.slam.yaml`（只差三处 `odom_topic`），启动时 `mission_params_file:=<选中的那份>`（单独起 mission 时用 `mission_stack_params_file:=`） | 想"起栈即切换、不用记参数"时用 |

**与地图无关**：`map_yaml_path` 在 yaml 里留空，由 launch 注入，换图不用改这份文件。

## 9. 其他船 / 工作区差异（澄丰 NX）

命令结构完全相同，只是路径与感知 launch 不同：

```bash
source ~/usv_nav_ws/install/setup.bash
ros2 launch usv_localization usv_map_odom_tf.launch.py              # RTK 版定位
ros2 launch workspace_nav nav2_boat.launch.py use_rviz:=false enable_mission_bridge:=true
ros2 launch usv_ardupilot_velocity_bridge ardupilot_velocity_bridge.launch.py
ros2 launch usv_docking docking.launch.py test_only:=false
ros2 launch dock_mission dock_mission.launch.py
source ~/jzw_ws/install/setup.bash && ros2 launch perception_launch cleaning_boat.launch.py   # 澄丰的感知
```

SLAM 版把定位换成 `ros2 launch lightning usv_loc_stack.launch.py start_driver:=true start_odom:=true use_robot_tf:=true map_dir:=<地图目录>`，并同样做 §0.2 的三处换源（`tf.send false` + 导航/归港 `odom_topic:=/slam/localization`）。

> 老流程若船端仍装 `workspace_ros`（本仓已移除该包，以船端为准）：`real_boat_bringup.launch.py` 的 `use_gnss_map_odom_tf:=false` 表示 `map→odom` 交给 SLAM，这是它与 SLAM 共存的开关。
