# 速度下发话题接口说明（嵌软对接）

> 上位机速度桥 `usv_ardupilot_velocity_bridge` 的输入话题接口。
> 平台遥控 / 任意控制源按下述约定发布速度指令，统一经过速度桥限幅后下发 MAVROS -> ArduPilot -> 推进器。

## 1. 话题定义

| 项目 | 约定 |
|---|---|
| 话题名 | `/cmd_vel_nav`（默认输入） |
| 消息类型 | `geometry_msgs/msg/Twist`（**裸 Twist，不是 TwistStamped**） |
| 发布 QoS | **reliable 或 best_effort 均可**（桥订阅端 best_effort，两种都能匹配） |
| 控制频率 | 建议 **20Hz 持续发布**（≥10Hz） |
| DDS / 域 | CycloneDDS，`ROS_DOMAIN_ID=5` |

### 消息字段（只用到两个）

| 字段 | 含义 | 单位 | 范围（桥内自动限幅） |
|---|---|---|---|
| `linear.x` | 前进速度，**+为前进** | m/s | 0 ~ 1.10 |
| `angular.z` | 转向角速度，**+为左转，−为右转** | rad/s | −0.28 ~ +0.35 |
| `linear.y` / `linear.z` / `angular.x` / `angular.y` | **必须填 0**（船不侧移/不升降，填了会被强制限为 0） | — | 0 |

### 测试命令（联调前可先用命令行验证链路）

```bash
# 以 0.5 m/s 前进 + 0.1 rad/s 左转，10Hz 持续发
ros2 topic pub --qos-reliability reliable --rate 10 /cmd_vel_nav \
  geometry_msgs/msg/Twist "{linear: {x: 0.5}, angular: {z: 0.1}}"
```

## 2. 安全行为（桥自动处理，嵌软侧无需重复实现）

1. **松手即停（dead-man）**：停止发布超过 **1 秒**，桥自动输出零速。遥控端只需"停止发送"即可停车，但**主动停车建议持续发全零 Twist**（走减速斜坡更平稳）。
2. **绝对限幅**：`vx ≤ 1.10 m/s`；`ω` 左转 ≤ 0.35、右转 ≤ 0.28 rad/s。
3. **vx-ω 可行域**：转向角速度大时自动下调前进速度（实船标定数据），保护"高速冲舵转不过来"。
4. **加速度斜坡**：前进加速 0.40 m/s²、减速 0.70 m/s²、转向 0.35 rad/s²，指令突变会被平滑。

## 3. 两种接入方式

| 方式 | 话题名 | 前提 | 适用 |
|---|---|---|---|
| A. 直接发默认话题 | `/cmd_vel_nav` | 无（当前船端版本即支持） | 快速联调 |
| B. 独立遥控话题 | 如 `/cmd_vel_remote` | 需船端把桥更新到"多输入话题"版本，并在启动参数 `input_cmd_topics` 里加上该话题 | 正式接入，与 Nav2 链路解耦 |

> 方式 B 需要的桥版本：`input_cmd_topics`（多话题输入）+ `input_cmd_qos`（best_effort 订阅）已合入 master，船端 colcon 重新 build 后生效。

## 4. 与 Nav2 自动导航共用此桥的注意事项

- 桥对多个输入源是**"后到覆盖"**语义：同一时刻若遥控和 Nav2 都在发指令，两者会互相抢占。
- **必须由上层保证互斥**：进入遥控模式时 Nav2/巡逻停止下发；退出遥控恢复导航。桥本身目前不做优先级仲裁。
- 遥控接管瞬间建议先连发几帧全零，再给运动指令。

## 5. 联调检查清单

- [ ] `ros2 topic info /cmd_vel_nav` 能看到嵌软端的 Publisher
- [ ] `ros2 topic echo /mavros/setpoint_velocity/cmd_vel_unstamped` 有桥的输出（需 MAVROS 已连飞控）
- [ ] 停发指令 1 秒后输出归零（dead-man 生效）
- [ ] 前进/左转/右转方向与船体实际动作一致（+x 前进、+z 左转）
- [ ] 遥控模式与自动导航切换时无指令抢占冲突
