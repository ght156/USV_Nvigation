# 导航与归港栈 船端部署依赖清单（给嵌软）

> 目的：嵌软打包船端（Jetson NX）运行环境时使用。本文列出**导航（Nav2）栈**与**归港（dock）栈**的全部软件包、系统依赖、外部组件、配置文件与启动方式。
> 整理日期：2026-09-14　整理方：导航侧（USV_NAV 仓）
> 现场操作细节另见 `docs/归港现场调试手册.md`、`docs/项目运行与联调.md`。

---

## 1. 运行平台与基础环境

| 项 | 值 | 说明 |
|---|---|---|
| 硬件 | Jetson NX（`ssh nx`，jetson@192.168.2.101） | ARM64 |
| 系统 | Ubuntu 22.04 ARM64 | Python 3.10 |
| ROS | **ROS 2 Humble**（ARM 版，`/opt/ros/humble`） | |
| DDS | `rmw_cyclonedds_cpp` | 必须与 MAVROS 侧一致，否则跨 RMW 的 service 会丢响应 |
| ROS_DOMAIN_ID | **5** | 主机/船端统一；船端 `.bashrc` 已配置 |
| 其他工具 | `tmux`（栈启动脚本依赖）、`colcon` | |

每个跑 ROS 的终端需要的环境：

```bash
source /opt/ros/humble/setup.bash
source ~/usv_nav_ws/install/setup.bash      # 本仓工作区（见 §2）
export ROS_DOMAIN_ID=5
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
# CYCLONEDDS_URI 只在主机（双网卡笔记本）需要，船端单网卡不用
```

## 2. 本仓（USV_NAV）提供的 ROS 包

打包时请从本仓 `src/` 取以下包，放入船端 `~/usv_nav_ws/src` 编译（建议 `colcon build --symlink-install`，改 yaml 配置免重编译）。

### 2.1 导航栈

| 包 | 位置（本仓） | 类型 | 职责 | 关键依赖 |
|---|---|---|---|---|
| `workspace_nav` | `src/USV_NAV/workspace_nav` | Python | Nav2 bringup + `mission_bridge`（上层任务 Action/服务接口）+ `nav_status_aggregator` + 电子围栏（zone_manager/zone_monitor） | `nav2_bringup`、`nav2_msgs`、`m_common`、`tf2`、`python3-yaml`、`utm`（pip） |
| `usv_localization` | `src/USV_NAV/usv_localization` | C++ | 发布 `map→odom` TF：读地图 yaml 的 `ref_gnss*` 锚点 + RTK（GNGGA/INSPVAA），GNSS 退化/跳变自动重置 | `bw_gi320_driver` 消息（嵌软提供，§3.3）、`tf2`、`yaml-cpp` |
| `usv_transforms` | `src/usv_transforms` | launch only | 整车 TF：`cleaning_boat.xacro` 经 `robot_state_publisher` 发 `base_link→各传感器 link` | `robot_state_publisher`、`xacro` |
| `m_common` | `src/m_common` | C++/接口 | 全部自定义 msg/srv/action（`NavigateTask`、`NavStatus`、`SetPause`、`NavSafetyEvent` 等）+ 日志/工具库 | `spdlog`、`rosidl_default_generators` |
| `usv_ardupilot_velocity_bridge` | `src/usv_ardupilot_velocity_bridge` | C++ | `/cmd_vel_nav` → `/mavros/setpoint_velocity/cmd_vel_unstamped`，自带 1s 看门狗超时清零 | `mavros_msgs` |

### 2.2 归港栈

| 包 | 位置（本仓） | 类型 | 职责 | 关键依赖 |
|---|---|---|---|---|
| `usv_docking` | `src/usv_docking` | Python | 精靠泊四节点：pose_estimator / fsm / motion_controller / safety；全程倒船、Tag 闭环 | `rclpy`、`tf2_ros`、`python3-yaml`；夹爪功能（默认关）懒加载嵌软 `usv_rs485_driver` |
| `dock_mission` | `src/dock_mission` | Python | 任务编排：Nav2 预泊 → 停稳 → 交接 usv_docking → 重试/出泊（入口验收已移除） | `m_common`、`std_srvs`、`tf2_ros`、`python3-yaml` |

### 2.3 船端脚本（随包带走）

- `scripts/start_nx_stack.sh` —— 船端导航栈一键启动（tmux 多窗口：rtk → mavros → localize → nav → bridge）
- 归港栈船端一键脚本 `~/start_dock_stack.sh`（船端已有，源在本仓部署流程，见调试手册 §1）

## 3. 本仓之外、需要嵌软/系统侧提供的组件

### 3.1 apt 安装的 ROS 包（Humble）

```bash
sudo apt install -y \
  ros-humble-nav2-bringup \        # Nav2 全家（planner/controller/bt_navigator/costmap 等随之装入）
  ros-humble-robot-localization \  # workspace_ros 声明依赖；实船默认不用 EKF（mavros_odom 后端），建议装上备用
  ros-humble-robot-state-publisher \
  ros-humble-xacro \
  ros-humble-tf2-geometry-msgs ros-humble-tf2-tools \
  ros-humble-cv-bridge \           # apriltag_localization 用
  ros-humble-rmw-cyclonedds-cpp \
  ros-humble-teleop-twist-keyboard # 调试可选
# MAVROS 注意：船上用的是源码编译的 ~/mavros_ws（含自定义 mavros_msgs/srv/GetMapOrigin，
# usv_localization 定位启动时要用；不要用 apt 版直接替代，见 §3.2）
```

系统库（编译期）：`libyaml-cpp-dev`、`libeigen3-dev`、`libpcl-dev`、`libopencv-dev`、`libspdlog-dev`、`python3-dev`。

### 3.2 MAVROS（嵌软负责）

- 船端跑**源码工作区 `~/mavros_ws`** 的 MAVROS（ArduPilot 模式）：
  `ros2 launch mavros apm.launch fcu_url:=/dev/ttyTHS1:921600`
- 飞控串口 `/dev/ttyTHS1`，波特率 921600。
- 导航/归港栈消费的 MAVROS 话题：
  - `/mavros/local_position/odom` → `odom→base_link` TF（车体里程计，**定位链路的硬依赖**）
  - `/mavros/gps_input/local` —— 速度里程计（usv_docking、dock_mission 实船配置使用）
  - `/mavros/setpoint_velocity/cmd_vel_unstamped` —— 速度指令输出（速度桥写入）
- 注意：`usv_localization` 启动时需要 `~/mavros_ws` 里的**自定义** `mavros_msgs/srv/GetMapOrigin`，否则 map→odom 不发布（`start_nx_stack.sh` 注释有记录）。

### 3.3 RTK 驱动（嵌软仓）

- `bw_gi320_driver` 实际运行在嵌软 `~/usv` 仓（`install/arm`）：
  `ros2 launch bw_gi320_driver bw_gi320_driver.launch.py`
- 其自定义消息包是 `usv_localization` 的编译依赖——**编译 `usv_nav_ws` 前必须先 source `~/usv/install/arm/setup.bash`**。

### 3.4 Livox MID360 激光雷达（避障）

- 驱动：`livox_ros_driver2`（以太网 UDP，雷达网段配置见 `docs/livox_mid_360_连接与驱动编译记录.md`）。

- Nav2 local costmap 的障碍观测源是 `/livox/lidar`（`nav2_params_chengfeng.yaml` 的 `livox_cloud`）——**不起雷达驱动 = 无避障**。

  

### 3.5 视觉感知（归港必需）

归港末端依赖 AprilTag 视觉定位（输出 `base_link→dock_frame` TF）。船端由感知 launch 一键拉起（三件套）：

```bash
ros2 launch perception_launch cleaning_boat.launch.py
# = video_camera_node（后相机）+ apriltag_localization + compressed_republish
```

- `apriltag_localization`：C++ 包，本仓 `src/apriltag_localization` 与嵌软 `~/usv/src/perception/` 各有一份；依赖 OpenCV / Eigen3 / PCL / yaml-cpp，AprilTag 检测库已随包内置（`add_subdirectory(apriltag)`），无需额外装 apriltag 库。
  （其 package.xml 的 `interface_msgs` exec_depend 是残留，代码未使用，可忽略。）
- 相机：后视 USB 相机（船尾朝坞，看坞上两个 tag）。

### 3.6 船坞夹爪（可选，默认关闭）

- `usv_docking` 的夹爪交互（`dock_claw_enabled=true` 才启用）调用嵌软 `usv_rs485_driver` 的 ControlDO / WaitIO action。
- 默认 `dock_claw_enabled=false`，**不装该包也能跑**；启用前需嵌软部署 `usv_rs485_driver`。

## 6. 启动顺序（船端现状）

导航栈（`~/usv_nav_ws/scripts/start_nx_stack.sh start`，tmux 会话 `nx_stack`；其中 rtk/mavros 是嵌软侧组件，脚本只是负责拉起）：

```text
1) rtk      bw_gi320_driver（嵌软 ~/usv 仓，见 §3.3）
2) mavros   mavros apm.launch fcu_url:=/dev/ttyTHS1:921600（嵌软 ~/mavros_ws，见 §3.2）
3) localize usv_localization usv_map_odom_tf.launch.py（map→odom）
4) nav      workspace_nav nav2_boat.launch.py use_sim_time:=false use_rviz:=false（含 mission_bridge）
5) bridge   usv_ardupilot_velocity_bridge
```

归港栈（`~/start_dock_stack.sh start`）：速度桥 + usv_docking 四节点 + dock_mission；视觉链由 §3.5 的感知 launch 拉起。

⚠️ 主机和船**不要同时**起归港栈（`/cmd_vel_nav` 会双发）。
