## 3. 正常归港流程

**船位由人遥控到位**（不用 AI 开船；辅助脚本 `scripts/dock_test/drive_to_staging.py` 备用）：
1. 船尾朝坞（后摄像头正对两个 tag），坞轴线延长线上，距坞 5~10m（实测可见上限 12.7m）
2. rviz 里两个 tag 都在画面中部、不贴边（相机俯仰偏高，tag 容易贴画面底边丢失）

**触发前检查：**
```bash
timeout 5 ros2 topic echo /docking/tag_visible | grep data | sort | uniq -c   # true 应占多数
ros2 topic echo --once /docking/pose_source    # VISION 为最佳
ros2 topic echo --once /docking/dock_pose      # 看 ex/ey 是否与实际相符（坞外 ex<0）
```

**触发与取消：**
```bash
# 触发（跳过 Nav2 预泊，直接走归港 FSM）
ros2 topic pub --once /gcs_dock/command std_msgs/msg/String "{data: '{\"action\":\"dock_only\"}'}"
# 触发（走 Nav2 预泊，失败会回预泊点重试；Nav2 未调好前别用）
ros2 service call /dock/mission/start std_srvs/srv/Trigger
# 取消（四连，dock_mission 取消不会撤 Nav2 目标，必须一起发）
ros2 service call /dock/mission/cancel std_srvs/srv/Trigger
ros2 topic pub --once /dock/cancel std_msgs/msg/Empty
ros2 service call /mission_bridge/cancel_mission std_srvs/srv/Trigger
# Nav2 三 action 的 CancelGoal 用 scripts/dock_tune_gui.py 的「取消归港」按钮最省事
```

> **`dock_only` vs `one_click`（2026-10-07 澄清）**：`dock_only` 只跑归港 FSM，失败**原地重试**，
> 不会把船带回预泊点（需人工开回）；`one_click`（`/dock/mission/start`、`/dock/home`、
> `{"action":"one_click_dock"}`）失败且 `needs_reapproach=true` 时会经 Nav2 回预泊点重来（最多 5 次）。
> 触发条件与全流程见 `docs/bug_debug/2026-10-07_归港REACQUIRE盲驾把船带走与锚点1m乱跳.md` §7.5。

**监测（另开终端）：**
```bash
ros2 topic echo /dock/status          # JSON：state/ex/ey/eyaw，每 0.1s
ros2 topic echo /docking/state        # FSM 状态：ACQUIRE_TAG→APPROACH_ENTRY→ALIGN_ENTRY→BACK_IN→FINAL_DOCK→DOCKED
ros2 topic echo /docking/pose_source  # VISION / ODOM_PREDICTION / INVALID
```
健康基准（2026-09-12 实测）：坞内静止 ex std≈5mm、eyaw std≈0.5°；VISION 下 measurement_age 中位 0.17s；丢 tag 后 age 线性上涨，>3s 进推算告警窗口。

**到位验收（2026-10-05 起，兴飞）**：不再以位置判成功——FINAL_DOCK 到 `final_target_x` 后进入**压紧段**低速续倒，**无线充电 `charging_status∈{1,5}` 且 `error_code==0` 稳定 2s，或 WaitIO 夹爪 DI(0x0003) 先到** → DOCKED。监控日志关键字："进入压紧段" → "夹爪已抓住（WaitIO）-> DOCKED" 或 "充电判据"。
（旧逻辑：`|ex+0.41|<0.15 且 |ey|<0.10 且 |eyaw|<3°` 持续 1s，配 `docked_*` 参数——已废弃，`docked_yaw_tol_deg`/`docked_hold_sec` 参数保留声明但 FSM 不再使用。）

**录制（每次归港必开）：**
```bash
./scripts/record_dock_data.sh start <标签>   # 存 /home/ght/usv_bags/dock_<时间>_<标签>
./scripts/record_dock_data.sh stop           # 自动打印各话题消息数，0 条会标红
python3 /home/ght/usv_bags/analyze_dock_bag.py <bag目录>   # 出 analysis_*.png + 统计
```

## 4. 异常 → 调参索引（都改 `src/usv_docking/config/docking.yaml`，改 yaml 后重启 launch 生效；或 `ros2 param set` 在线改）

|---|---|---|

| 到位判不上/误判（旧逻辑，已废弃） | `docked_x_tol`/`docked_y_tol` 仍作压紧段进入窗口；`docked_yaw_tol_deg`/`docked_hold_sec` 不再使用 | 见 §3 到位验收 |
| 临界距离 VISION↔推算互弹 | `approach_tag_loss_grace_sec`(3s)/`align_tag_loss_grace_sec`(5s)（fsm）；`odom_prediction_timeout`/`align_odom_prediction_timeout`（safety，须大于 FSM 宽限） | 丢 tag 宽限 |
| 锚点被坏帧带偏 | `seed_frames`/`seed_max_spread_m`/`max_position_jump`/`max_yaw_jump_deg`（estimator） | 现 8帧/0.4m/0.6m/20° |
| 掠射角观测把锚点带歪/换泊位后锚点锁死 | `reloc_max_yaw_jump_deg`(10°)/`reloc_guard_escape_sec`(3.0)（estimator） | 锚点重定位守卫：簇 yaw 差超门限疑似伪影不重定位；簇持续超窗口判定真实移位放行 |
| REACQUIRE 原地打转/干等 | `reacquire_drive_max_sec`(10.0)/`reacquire_drive_max_dist_m`(5.0)（fsm） | 丢 tag 但锚点活着、且船在 5m 内时受控对准并接近虚拟坞位；同一会话内累计预算，用完退回 HOLD |
| 相机帧率低时 tag_visible 抖动 | `tag_timeout`（estimator，现 0.30s） | 检测间隔 >此值就会闪断；相机 2Hz 时放宽到 0.8 |
| 判稳等不住（水流推） | `approach_stop_speed`（fsm，现 0.15 m/s，用 /mavros/gps_input/local 对地速度） | 顶流停船对地速度仍可≈0；顺流漂等判稳时才需要放宽到 0.25 |
| 横向收敛慢/荡秋千 | `ky_back`(0.80)/`kyaw_back`(0.60)/`approach_crab_deg`(8°)（controller） | ky_back 决定收敛长度=1/ky |

| 水流/风大 | 不用专门调参：全程视觉闭环 20Hz，缓变扰动自动抵消；瞬态有 `violation_cycles`(10) 防抖 | 差速双推进正是控制器假设模型（v+ω） |

## 5. 已知问题与处置（2026-09-12 实测发现）

0. **运动能力实测**（`/tmp/motion_probe.py` 船上跑 + bag TF 真值分析）：线速度充足（倒退 -0.45→实测 0.47m/s，前进倒退基本对称）；**转向是瓶颈：角速度封顶 ~0.13 rad/s**（cmd 0.35 也只到 0.135）。控制器限幅已按实测改：max_yaw_rate 0.15 / search_angular_speed 0.13 / back_in_max_yaw_rate 0.12。⚠️ 反馈话题 /mavros/gps_input/local 的 twist 坐标系/符号与机体系不一致，测能力只能用 TF 位移，别用它判速度方向（FSM 的 approach_stop_speed 只用模长，无碍）。水流本底 0.1~0.3 m/s。
0.1 **docking.launch.py 的 test_only 默认 true**：不显式传 `test_only:=false` 控制器只发 /docking/cmd_vel_test，船不动且话题静默。船端 start_dock_stack.sh 已带。
0.2 **入口校验（entry_validator）已于 2026-09-15 整体移除**：它的 origin_map 吃 FC-odom 系坐标（不是 map），**飞控每次重启原点都变、必须重填**，且 yaw 门控因与船尾朝坞约定冲突早已用 yaw_max=3.15 实质关闭、ey 因杆臂放宽到 1.5m——防错价值抵不过每次重启重填的成本。删除范围：节点 `dock_entry_validator`、`dock_enu` 坐标变换、FSM 的 ENTRY_VALIDATE 状态、`dock_database.yaml` 入口几何段。现在停稳（SETTLE）后直接交接精靠泊，到点把关由 Nav2 docking_goal_checker（0.6m/0.15rad）承担。**飞控重启后不再需要重填任何 dock 几何。**
0.3 **APPROACH 段无安全兜底**：safety 横向/艏向检查只覆盖 BACK_IN/FINAL_DOCK。APPROACH 里 ey 曾冲到 2.4m 无告警（撞走廊那次）。TODO: 给 APPROACH 加宽松限幅（如 |ey|>1.2 持续 3s 中止）。
0.4 **ros2 bag record 在 NX 上疑似 OOM 闪退**（两次 1GB+ bag 无 metadata）：db3 可 sqlite 直读但 ros2 bag play 放不了。录制时去掉相机话题可大幅减压。
0.5 **ros2 CLI 在船上偶发卡死**（daemon/discovery 问题）：用 rclpy 脚本直测，或 `ros2 daemon stop && ros2 daemon start`。

1. **tag0 视野盲区**：方位角 >+20° 先丢 tag0，只剩单码时 7m 外 yaw 摆动 16~52°（估计器 20° 跳变拒绝会挡一部分）。治本：调 tag0 安装位/相机朝向。
2. **相机俯仰偏高**：tag 容易贴画面底边导致零星检测。遥控摆位时让 tag 到画面中部。
3. **detections/图像录不进主机 bag**（跨机数据面抖动，TF 反而通）：船上本地补录，或事后分析用 TF 里的 apriltag 帧（`analyze_dock_bag.py` 就是这么做的）。
4. **船/主机时钟差 ~0.85s**（船快）：会让估计器测量龄期出现负值/偏大。上船先对时（`sudo chronyd`/timesyncd 同步同一 NTP）。
5. **船上 polkitd 偶发占 90%+ CPU**：抢 CPU 拖慢相机（10fps 掉到 1.8Hz）。`sudo systemctl restart polkit`。
6. **ROS 节点清理**：`ros2 launch` 父进程死后子进程不退，用 `pkill -f "docking_fs[m]"` 这类模式杀（见 工作进度汇报.md）。
7. **（2026-10-05）节点残留是头号运维事故**：同一角色多份节点并存会导致 modbus 总线冲突（rs485 ×N 抢网关）、参数不生效、"鬼节点"吃掉服务调用。重启一律走栈脚本 `stop`/`start`（已改 setsid+进程组停止）；排查先 `pgrep -af` 清点。详见 `bug_debug/2026-10-05_节点残留致modbus冲突与鬼节点.md`。
8. **（2026-10-05）"tag 检得到但归港用不了"先查 TF**：`tf2_echo base_link camera_back_video_link` 和 `tf2_echo base_link dock_frame`；栈脚本 localization 项必须 `publish_robot_tf:=true`。详见 `bug_debug/2026-10-05_TF缺失与CycloneDDS-eth1环境坑.md`。

## 7. 自动测试 Playbook（给后续 AI/接手人）

以下流程已在 2026-09-12 实船验证，可直接复现。

### 7.1 前置条件
- 船端全栈在跑（`~/start_all.sh start`），确认：
  - `ros2 topic echo --once /docking/state` → `IDLE`
  - `ros2 topic echo --once /docking/tag_visible` → `true`（镜头里能看到 tag）
  - `ros2 topic echo --once /docking/pose_source` → `VISION`
- 主机端：`source install/setup.bash`，录制已开 `./scripts/record_dock_data.sh start <标签>`

### 7.2 一键测试脚本（都在 `scripts/dock_test/`，在船上跑）

| 测试 | 脚本 | 关键参数/说明 |
|------|------|-------------|
| **运动能力标定** | `motion_probe.py` | 约 90s 自动完成。分析用 `motion_bag_analyze.py <bag>` |
| **归港单跑** | `dock_watch.py` | 触发后监视，ey>1.0 持续 1s 自动取消 |
| **出港→再归港循环** | `dock_cycle.py` | 全流程无人干预，等门触发 |
| **状态快查** | `dock_snap.py` | 船上 ros2 CLI 卡死时用这个（rclpy 直读） |

### 7.3 触发门（dock_cycle.py 里的 GATE）
- ex ∈ (-6.5, -1.2)，|ey| < 0.8（根据 2026-09-12 实测放宽；**有流时别超 6.5m**，宁可人工开近点）
- 若船被流推出门（ex<-6.5），人工开回再试，不要硬触发

### 7.4 常见问题速查
| 现象 | 原因 | 处置 |
|------|------|------|
| 发了指令船不动 | `docking.launch.py` 的 `test_only` 默认 true，只发 /docking/cmd_vel_test | `ros2 launch usv_docking docking.launch.py test_only:=false` |
| 船在坞口打转不动 | 转向饱和（实测 0.13 rad/s），水流在压 | 取消，把船开得更正对再触发 |
| 检测不到 tag | tag 贴画面底边/太小，或船位太偏 | 遥控调整让 tag 到画面中部，5~10m 内 |
| 归港时 ey 超 0.5 | 水流横向推，APPROACH 无安全兜底 | 用 `dock_watch.py`（它会自动取消） |
| 归港开始背光板不亮 | `backlight_enabled=false`，或 `/set_do` 服务不可用（日志有 "船坞背光" 告警），或 `dock_claw_open_on_start=true` 时驱动 ControlDO 把 bit1 抹掉（见 `bug_debug/2026-10-08_...md`） | 查 `docking_fsm` 日志的 "背光: 写 DO 0x0002"；手工验证 `ros2 service call /set_do usv_rs485_driver/srv/SetDO "{digital_output: 2}"` |
| 出港车不动/爪子不放 | `WAIT_DOCK_RELEASE` 抬爪失败 → `FAILED` 停车（爪子可能仍扣着，禁止盲动） | 看 `dock/status` 的 `abort_reason` 是否 `DOCK_RELEASE_FAILED`；确认 `dock_claw_release_on_undock=true` |

### 7.5 验收标准
- DOCKED 时 |ex - (-0.41)| < 0.15m，|ey| < 0.10m，|eyaw| < 3°
- 出港完成时 ex ≈ -3.0（惯性滑到 -4.5 正常）
- 有流（0.2m/s+）环境下允许 ey 在 BACK_IN 段有 ±0.3m 波动，但不得持续超 0.5s
