# 2026-10-15 出港背光全掩码写清夹爪位，船拖着坞跑

## 基本信息

- 日期：2026-10-15
- 船/工作空间：兴飞船（hkzl），`~/usv-main`
- 引入方：船端归港栈当日的"出港点背光"改动（`docking_fsm`）
- 数据来源：`~/logs/xingfei_stack/docking.log`、现场目击

## 现象

出港时夹爪刚抬开又闭合，船拖着船坞跑。

## 根因（已确证）

兴飞夹爪**靠线圈保持打开**：`ControlDO` 写 `kDOOnMask=0x0001` 把 bit0 通电抬爪，
掉电（bit0=0）即弹簧闭合。

当日的改动让 `docking_fsm` 在出港会话点亮背光：`/dock/undock` 时
`_backlight_session_begin("出港")`、进 `UNDOCK_EXIT` 时立即补写、之后 20s 保活。
而 `set_do` 是 **16 位全掩码写**——FSM 写背光 `0x0002` 的同时把 bit0 写成了 0，
夹爪线圈掉电，爪子在船驶出途中闭合，钩住船体拖坞。

时序：`WAIT_DOCK_RELEASE`（驱动 ControlDO 抬爪，bit0=1，FSM 按约定不写 DO）
→ 成功进 `UNDOCK_EXIT` → **FSM 立即写 `0x0002`（bit0 被清，夹爪闭合）** → 船带坞跑。

这与 2026-10-08 拆分时的设计约束冲突却不自知：出港段 DO 归驱动（ControlDO），
FSM 任何 set_do 写都会动到夹爪位。

  写 `0x0002`/`0x0000` 不改变 bit0。

  `exit_blind_timeout_sec`(15s) 控制盲开距离。现场确认可接受（盲开距离受控即可）。

## 教训 / 后续如要"出港点背光"

`set_do` 全掩码写下，出港段点背光**必须**把夹爪位一起带上（写 `0x0003`），
且要同时解决：

1. 夹爪线圈持续通电的电气允许（驱动 60s 自动清 DO 就是为保护线圈加的）——
   **需嵌软确认**；
2. 驱动 ControlDO 成功后 60s `writeDO(0x0000)` 全清会在出港中途把夹爪+背光
   一起抹掉，FSM 保活补写前有空窗——需嵌软在出港场景关闭/放宽自动清 DO。
