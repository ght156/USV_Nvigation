# 2026-10-21 局部代价图"水面全是障碍"：清扫杆/水雾遮蔽 + 观测源改话题

## 现象

局部代价图大片实心致命区，船前方和水面被当成障碍。坞内清图后 12 s 重新标回 3300+
格；开到开阔水面后致命格继续涨到 9700+，其中 **96~99% 的致命格当前点云完全不支持**
（nav_diag compare 实测 9708 格中 9697 格 stale）。

## 排查结论（不是 TF 问题）

- 雷达 TF（base_link→livox_frame，pitch -43.85° yaw 180°）与 2026-09-28 水面标定一致；
  用雷达内置 IMU 实测重力方向，与标定姿态夹角 **0.00°**——安装姿态没动，TF 不改。
- 运行参数与 yaml 一致（观测源参数 configure 时读一次，在线改无效，见 2026-10-10 记录）。

## 根因（两条）

1. **持续标记源**：船头正前 0~0.8m 的清扫杆及其搅动的水雾（实测船体系
   x 2.75~3.46 / y -1.0~+1.25 / z -0.15~+0.25，每帧 ~450 点），在观测源距离/高度窗口内，
   每帧都被标成障碍。杆随船动、且杆自身就是射线端点 → **射线清除永远清不掉它**。
2. **清除缺失**：斜装雷达（仰 43.9°）在开阔水面几乎没有水面回波 → 没有清除射线扫过
   低空区域，历史标上的格子在 rolling 窗口里越积越多（同样的原因，岸测时地面回波
   能提供稠密清除射线，水上没有）。

## 处理

**2026-10-21 晚决定：联调期间局部代价图点云障碍源默认关闭**
（`voxel_layer.enabled: false`，"水面 ghost 尚未调好"）。以下过滤机制已就位备用：
恢复时把 enabled 改回 true（支持在线改）即可，观测源接的是过滤云，清扫杆/水雾不会再入图。

新增 `workspace_nav/livox_cloud_filter.py`（console_scripts: `livox_cloud_filter`）：

- 订阅 `/livox/lidar`，静态 TF 只查一次，把点变换到 base_link 系，丢弃落在
  `mask_boxes`（扁平 6 元组数组，支持在线改）内的点，**原坐标系原样转发**
  （只删点，字段/时间戳不丢；Livox 点云字段类型不一，`read_points_numpy` 不可用，
  按 fields 布局自建 numpy dtype 解析）。
- 默认盒（覆盖杆/水雾区，不碰左右舷真实物体）：
  `x 2.70~3.70 / y -1.20~+1.40 / z -0.40~0.65`（下贴观测源 min_obstacle_height，
  上盖 voxel 层 max_obstacle_height 0.6）。
- 发布 `/livox/lidar_filtered`；`nav2_params_xingfei.yaml` 局部代价图观测源
  `livox_cloud.topic` 改为它（全局 voxel_layer 仍 disabled，未动）。
- `nav2_boat.launch.py` 加该节点（respawn；它挂了代价图将无观测，比没装更危险）。
- 在线验证（坞外水面）：原始云 B 盒内 2232 点/5 帧 → 过滤后 0，其余点不受影响。
- mission_bridge 增加任务级清图：新任务发第一个航点前异步清一次局部代价图
  （`clear_costmap_on_mission_start: true`）；运行期周期清图做成可选参数
  `costmap_clear_period_sec`（默认 0=关——整清会连真障碍一起抹掉，重标需若干帧，
  长跑任务实测仍积鬼影时再开 300~600）。参数已写入 mission_stack.xingfei.yaml。

部署：船上运行栈是 `~/usv-test`（install 非 symlink，团队惯例直接覆盖 install 树 +
留 .bak）。本次同步：`usv-test/install/arm/.../{share/config,share/launch,site-packages,lib/}`
+ `usv-main/src/USV_NAV/workspace_nav/`（源码仓），本地仓已同步船端较新版本
（船端 10-21 已把 min_obstacle_height -0.35→-0.30、修过 use_rviz 'flase' 笔误，均已采纳）。

**重启才生效**：观测源 topic/参数只在 configure 时读；start_cleaning_boat_xinfei.sh
是 `wait -n` 监管——任一 launch 退出会整栈 teardown，故只能整栈停起
（kill 监管 bash → 重新 `bash ~/usv-test/start_cleaning_boat_xinfei.sh`）。

## 遗留 / 后续

- 每帧 ~1.76 万点在光心 0.2m 内（被 min_range 1.4 滤掉，不入图但白占 CPU/带宽）：
  疑似雷达窗口水珠/脏污，靠泊后擦一次雷达罩再对比。
- 若过滤+抬 -0.30 后仍有缓慢积累（船行波/浪花在 -0.30~0.6 带、1.4m 外的零星标记），
  下一步：在线把 `voxel_layer.mark_threshold` 调 2（即时生效），或加一个
  marking:false/clearing:true 的合成水面扫掠观测源。
- 顺带发现（未处理）：map→odom 把船定位在全局地图边角 (0.18,0.19)，船周 30m 内
  74% 在地图外、图上其余全是"陆地"，且 gps_fix=0——定位/地图对齐有独立问题，
  局部代价图不受影响，全局规划需另查。
- map_view.launch.py 的独立代价图仍订阅原始 `/livox/lidar`（调试看图用，未改）。
