# 归港任务对接文档（嵌软状态机 ↔ dock_mission）

> 面向嵌软/决策层状态机：如何通过 `dock_mission` 触发并跟踪「一键归港 / 仅精靠泊 / 出泊 / 取消」。
> 实现包：`src/dock_mission`（任务编排 FSM）→ 交接 `src/usv_docking`（精靠泊四节点）。
> 相关文档：`docs/导航与归港异常告警.md`（告警清单）、`docs/特殊情况码汇总.md`（21xx 终态码）、
> `src/usv_docking/docs/架构与上层接口.md`（精靠泊内部架构）。

---

## 1. 系统位置与职责划分

```text
嵌软状态机（决策层）
   │  触发：/gcs_dock/command、/dock/home、/dock/mission/start|cancel
   ▼
dock_mission（编排 FSM，本对接的直接对象）
   │  预泊：调用 mission_bridge/send_waypoints（WGS84） → Nav2
   │  完成判定：订阅 /task_event（mission_bridge 生态）
   │  交接：/dock/start → usv_docking；/dock/cancel、/dock/undock
   ▼
usv_docking（精靠泊，船内节点，嵌软不直接对接）
```

嵌软**只**需要消费本文 §2（触发）和 §3（状态/事件上报）。
`/dock/status`、`/docking/*`、`/dock/speed_authority` 等是船内联调话题，**不要**作为对接依据。

---

## 2. 触发接口（嵌软 → 船）

### 2.1 `/gcs_dock/command`（推荐主入口）

- 类型：`std_msgs/msg/String`，data 为 UTF-8 JSON；QoS：RELIABLE depth=10
- topic 名可由参数 `gcs_dock_command_topic` 改

```json
{
  "action": "one_click_dock",   // 必填：one_click_dock | dock_only | undock | cancel
  "mission_id": "m001",         // 可选：任务标识，原样回填到 status/event
  "command_id": "c1"            // 可选：指令标识，原样回填到 status/event
}
```

| action | 语义 | 流程 |
|--------|------|------|
| `one_click_dock` | 一键编排归港 | Nav2 预泊 → 停稳 → 入口验收 → 交接精靠泊 → 监控至完成 |
| `dock_only` | 仅精靠泊（船已在预泊点附近） | 跳过 Nav2 预泊，直接入口验收 → 交接 |
| `undock` | 出泊 | 交接 usv_docking 前进离坞 → 监控至完成 |
| `cancel` | 取消当前归港会话 | 任何时刻可发；幂等 |

- 商用单坞：**JSON 不含 `bay_id`**（泊位由船端配置 `dock_mission.yaml: bay_id` + `config/dock_database.yaml` 选定）。
- 非法 JSON 或未知 action：丢弃并打 warning，**不上报事件**（嵌软应靠 status 超时兜底）。
- 忙时（已有会话或状态非 IDLE/SUCCEEDED/FAILED/CANCELLED）拒绝，同样只打 warning；嵌软应以下发后 5s 内是否收到 `DOCK_TASK_ACCEPTED` 判断受理与否。

### 2.2 `/dock/home`

- 类型：`std_msgs/msg/Bool`，`data: true` = 一键归港（等价 `one_click_dock`，无 mission_id/command_id）
- `data: false` 忽略。topic 名可由参数 `dock_home_topic` 改

### 2.3 Service（Trigger）

| 服务 | 类型 | 语义 |
|------|------|------|
| `/dock/mission/start` | `std_srvs/srv/Trigger` | 一键归港；`success=true` 表示受理，`message` 含模式 |
| `/dock/mission/cancel` | `std_srvs/srv/Trigger` | 取消；`success=true` 幂等 |

## 3. 上报接口（船 → 嵌软）

### 3.1 `/dock_task/status`（周期状态，约 5Hz）

`std_msgs/msg/String`，data 为 UTF-8 JSON；QoS：RELIABLE depth=10。

```json
{
  "schema_version": 1,
  "run_state": "RUNNING",            // IDLE | RUNNING | SUCCEEDED | FAILED | CANCELLED
  "phase": "STAGING",                // IDLE | STAGING | DOCKING | UNDOCKING
  "mode": "one_click",               // one_click | dock_only | undock | null
  "dock_active": true,               // 归港会话是否存活（成功后自动释放=false）
  "retry_count": 1,
  "retry_max": 3,
  "needs_manual_takeover": false,    // true = 请求人工接管（重试耗尽）
  "needs_reapproach": false,         // true = 精靠泊失败需重 Nav 预泊
  "camera_ready": true,              // 预留（相机握手 TBD），当前恒 true
  "error_code": 0,                   // 预留，当前恒 0（终态码映射见 §5）
  "error_message": null,
  "mission_id": "m001",
  "command_id": "c1",
  "elapsed_sec": 98.5,
  "event_ack_ok": true,          // 最近一次关键事件是否已被上层确认收到（ACK）
  "event_ack_failures": 0        // 累计未能确认收到的事件数（>0 表示事件通道异常）
}
```

`phase` 语义：`STAGING` = Nav2 预泊/停稳/入口验收；`DOCKING` = 已交接 usv_docking 精靠泊；`UNDOCKING` = 出泊中。

嵌软关键判据：

| 判定 | 条件 |
|------|------|
| 执行中 | `dock_active==true && run_state=="RUNNING"` |
| 成功闭环 | 收到 `DOCK_SUCCEEDED`（service 回 ACK），且 status 回到 `dock_active==false && run_state=="IDLE"` |
| 需人工接管 | `needs_manual_takeover==true`（或 `MANUAL_TAKEOVER_REQUESTED` 事件） |

### 3.2 `/dock_task/event`（事件上报 service，状态机为 server）

> 事件通道已从 fire-and-forget 话题改为 **service**，由嵌软状态机实现 server、船端作 client，
> **确保上层收到关键事件后回 ACK**。替代原 `/dock_task/event` 话题。

- 类型：`m_common/srv/DockTaskEvent`（定义：`src/m_common/srv/DockTaskEvent.srv`，注释副本 `docs/srv/DockTaskEvent.srv`）
- QoS：RELIABLE（ROS2 service 语义，请求-响应；无 depth 概念）

**Request**（船 → 嵌软）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `event` | `string` | 事件名（必填） |
| `mission_id` | `string` | 任务标识（可空，原样） |
| `command_id` | `string` | 指令标识（可空，原样） |
| `detail` | `string` | UTF-8 JSON 对象；无 detail 时空串（等价 `{}`） |
| `stamp_sec` | `float64` | 船端事件时间戳（epoch 秒；0=未提供） |

**Response**（嵌软 → 船，ACK）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | `bool` | `true`=上层已受理（ACK）；`false`=拒绝/未识别 |
| `message` | `string` | 结果说明 / 失败原因 |
| `ack_id` | `string` | 上层回执唯一 id（幂等/去重；可空） |
| `ack_stamp_sec` | `float64` | 上层确认时间戳（epoch 秒；0=未提供） |

| event | detail | 触发时机 |
|-------|--------|----------|
| `DOCK_TASK_ACCEPTED` | `{mode, require_camera}` | 命令受理（对触发命令的确认） |
| `UNDOCK_TASK_ACCEPTED` | `{mode}` | 出泊命令受理 |
| `DOCK_STAGING_STARTED` | — | Nav2 预泊点已下发（每次重试各一条） |
| `DOCK_HANDOFF` | — | 已发布 `/dock/start`，进入精靠泊 |
| `UNDOCK_HANDOFF` | — | 已发布 `/dock/undock`，进入出泊 |
| `DOCK_SUCCEEDED` | `{elapsed_sec, mode}` | 靠泊成功，会话随后自动关闭 |
| `UNDOCK_SUCCEEDED` | `{elapsed_sec, mode}` | 出泊成功 |
| `DOCK_FAILED` | `{reason, retry_count, needs_manual_takeover, needs_reapproach}` | 失败终态 |
| `DOCK_CANCELLED` | — | 已取消 |
| `MANUAL_TAKEOVER_REQUESTED` | `{reason, retry_count}` | 重试耗尽，请求人工接管（先于 DOCK_FAILED） |

- **靠泊成功以 `DOCK_SUCCEEDED` 为准**，不要解析 `/dock/status` 的 `success` 字段（船内联调全量字段）。
- `SUCCEEDED`/`CANCELLED` 是瞬态：status 的 run_state 随后回到 `IDLE`。
- 船端对每个事件发起 service 调用，`event_ack_ok`/`event_ack_failures`（见 §3.1）指示上层是否确认收到。
  嵌软应将 `success` 置 `true` 表示已记录/处理；若事件已被处理过（重复），按幂等返回 `true`。
  
  > 默认上层不可达不阻塞船侧 FSM（仅告警并累计 `event_ack_failures`）；如需严格模式，船侧可据此判定。
- 船侧另向可选观察话题 `/dock_task/event_log` 发布同 JSON（参数 `dock_task_event_log_topic`，置空关闭），供日志/联调。

## 4. 交互时序

### 4.1 一键归港成功

```text
嵌软 → /gcs_dock/command {action:"one_click_dock", mission_id, command_id}
船   → service /dock_task/event DOCK_TASK_ACCEPTED      （受理确认，嵌软回 ACK）
船   → service /dock_task/event DOCK_STAGING_STARTED    （预泊点已下发 Nav2，嵌软回 ACK）
       status: run_state=RUNNING, phase=STAGING
船   → service /dock_task/event DOCK_HANDOFF            （停稳+入口验收通过，交接精靠泊，嵌软回 ACK）
       status: phase=DOCKING
船   → service /dock_task/event DOCK_SUCCEEDED          （精靠泊完成，嵌软回 ACK）
       status: run_state=IDLE, dock_active=false
嵌软 ← 判定成功闭环
```

> 以上每条 `service /dock_task/event` 调用，嵌软（server）均须回 `success=true` 确认收到。
> 若嵌软未实现 server 或不可达，船侧按 §3.2 告警并累计 `event_ack_failures`，但不阻塞归港 FSM。

### 4.2 失败与重试

- 预泊/验收类失败：自动重发预泊，最多 `retry_max`（默认 3，参数 `staging_retry_max`）次；每次重试重发 `DOCK_STAGING_STARTED`。
- 精靠泊上报 `needs_reapproach`：回预泊流程重试，status `needs_reapproach=true`。
- 重试耗尽：event `MANUAL_TAKEOVER_REQUESTED` → `DOCK_FAILED`，status `needs_manual_takeover=true`。
- 精靠泊失败且不可重进：`DOCK_FAILED`（`needs_manual_takeover=false`）。
- 人工接管后如需复位归港栈：发 `cancel`（回到 IDLE，幂等）。

### 4.3 出泊

`action:"undock"` → `UNDOCK_TASK_ACCEPTED` → `UNDOCK_HANDOFF` → `UNDOCK_SUCCEEDED` / `DOCK_FAILED`。
仅当无活动会话时受理。

## 5. 与特殊情况码（21xx）的映射建议

`/dock_task/event`、`/dock_task/status` 不直接携带 21xx 码（`error_code` 字段预留恒 0），
嵌软按下表把终态映射到 `特殊情况码汇总.md` 的返回船坞段：

| 归港侧终态 | 建议映射 |
|-----------|----------|
| `DOCK_FAILED`，reason 含 tag/acquire/未发现类（如 `ACQUIRE_TAG timeout`） | `2101 DOCK_NOT_FOUND` |
| `DOCK_FAILED`，reason 为对准/接近/超时/中止类（approach/align/back_in/abort 等） | `2102 DOCK_APPROACH_FAILED` |
| `DOCK_FAILED`，reason 为终局对接/锁定类（final_dock/docked 判稳失败） | `2103 DOCK_LOCK_FAILED` |
| `MANUAL_TAKEOVER_REQUESTED` | 同上按 reason 归类 + 人工接管告警 |
| `DOCK_SUCCEEDED` / `UNDOCK_SUCCEEDED` | 终态成功码（按汇总表"非故障"语义） |

精确 reason 字符串清单见 `docs/导航与归港异常告警.md`。

## 6. 互斥与前置条件（嵌软须知）

1. **与主导航任务互斥**：归港预泊通过 `mission_bridge/send_waypoints` 下发，会**抢占**正在执行的航线任务（等效 explicit_replan）。嵌软应保证：主导航任务结束/取消后再下归港；归港会话期间不要再下发新航线。
2. **速度互斥由船内保证**：精靠泊阶段 `/cmd_vel_nav` 由 usv_docking 接管，停稳静默后交还；速度桥（usv_ardupilot_velocity_bridge）有 1s 看门狗兜底清零。
3. **触发幂等**：`cancel` 任何时刻可发；重复 `one_click_dock` 在忙时会被静默拒绝，以 `DOCK_TASK_ACCEPTED` 为受理凭据。
4. **无心跳即失效**：若 `/dock_task/status` 停发超过数秒，视为归港栈离线（嵌软兜底告警）。
5. 触发前请确认 `bay_id` 指向的泊位已在船端 `config/dock_database.yaml` 标定（实船 RTK 标定）。

## 7. 调试示例（开发机）

```bash
# 触发
ros2 topic pub --once /gcs_dock/command std_msgs/msg/String \
  "{data: '{\"action\": \"one_click_dock\", \"mission_id\": \"m001\", \"command_id\": \"c1\"}'}"
ros2 topic pub --once /dock/home std_msgs/msg/Bool "{data: true}"
ros2 service call /dock/mission/start std_srvs/srv/Trigger "{}"

# 取消
ros2 topic pub --once /gcs_dock/command std_msgs/msg/String "{data: '{\"action\": \"cancel\"}'}"
ros2 service call /dock/mission/cancel std_srvs/srv/Trigger "{}"

# 观察
ros2 topic echo /dock_task/status
ros2 topic echo /dock_task/event_log     # 可选观察流（事件 JSON，见 §3.2）

# 事件上报 service（嵌软实现 server 前，可用 mock 顶替）
python3 scripts/dock_test/mock_event_server.py   # 回 ACK，打印收到的事件
ros2 service call /dock_task/event m_common/srv/DockTaskEvent \
  "{event: 'DOCK_SUCCEEDED', mission_id: 'm001', command_id: 'c1', detail: '{\"elapsed_sec\": 142.5, \"mode\": \"one_click\"}', stamp_sec: 0.0}"
```
