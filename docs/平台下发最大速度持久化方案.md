# 平台下发最大速度：持久化方案（待平台确认）

> 状态：**待平台确认是否实施**（2026-09-01 记录）
> 背景：平台拟在下发航线任务时附带导航最大速度；Nav2 在线改参重启后丢失，需持久化。

## 需求

1. 平台在下发航线任务（`SendWaypoints`）时附带导航最大速度。
2. 重启后：若存在之前平台设置的持久化最大速度 → 用它；否则 → 用参数文件默认值（`desired_linear_vel: 0.5`）。
3. 提供"清除"接口：清除后回退到参数文件默认值。

## 关键事实（已核实）

- 控制器是 RegulatedPurePursuit（RPP），没有 `max_vel_x`，**实际巡航速度就是 `FollowPath.desired_linear_vel`**（`src/USV_NAV/workspace_nav/config/nav2_params_real_mavros.yaml:91`，当前 0.5 m/s），该参数支持在线动态修改。
- Nav2 原生 `/controller_server/speed_limit` 话题只能"往下压"，平台要求的速度若高于 0.5 就提不上去，语义不符，**不采用**。
- 仓库内目前无人调用 `/controller_server/set_parameters`，需新增一个参数客户端。
- 持久化有现成模式：`zone_manager._persist/_load_persisted` + `atomic_write_json`（`gps_map_conversion.py:217`），照抄即可。
- 下游安全硬顶：`ardupilot_velocity_bridge` 的 `max_linear_x: 1.10`（只启动时读取），平台速度超过它会被桥截断。
- `SendWaypoints` 服务端仅 `mission_bridge.py` 使用，客户端在平台侧（本仓库无）；**加字段后消息 hash 变化，平台侧客户端必须同步重新编译/生成，否则服务调用不通**。
- 实船绕过 velocity_smoother（订阅 `/cmd_vel_nav`），无需动 smoother。

## 改动方案

### 1. 接口：`src/m_common/srv/SendWaypoints.srv` 增加字段

```
m_common/MissionWaypoint[] waypoints
string mission_id
string command_id
# 最大线速度 m/s；<=0 或 NaN 表示本次不下发（不改变当前生效值）
float32 max_speed
```

- 同步更新镜像文档 `docs/srv/SendWaypoints.srv`，以及 `docs/nav_task_interface.md`、`docs/decision_nav对接文档.md` 中对该 srv 的引用说明。

### 2. `mission_bridge.py` 新增最大速度管理（约 120 行）

新增参数（`__init__` 声明区）：
- `max_speed_persist_path: ""`（默认定位 `workspace_nav/json/max_speed.json`，复用 zone_manager 的 `_default_persist_path` 查找逻辑）
- `default_max_speed: 0.5`（须与 nav2_params 的 `desired_linear_vel` 一致，注释说明）
- `max_speed_hard_cap: 1.1`（与桥 `max_linear_x` 对齐，超出钳位+告警）
- `controller_speed_param_node: "/controller_server"`（参数客户端目标）

新增逻辑：
- `_load_persisted_max_speed()`：启动时读 JSON `{"max_speed": 0.8}`；文件不存在 → 不动 Nav2（参数文件值生效），记 info 日志。
- `_persist_max_speed(v)` / `_clear_persisted_max_speed()`：`atomic_write_json` 写 / 删文件。
- `_apply_max_speed(v)`：`AsyncParameterClient`（`rcl_interfaces/srv/SetParameters`）异步设置 `/controller_server` 的 `FollowPath.desired_linear_vel`；用**定时器重试**（每 2s 一次，最多约 10 次，成功后停表），覆盖 controller_server 晚于 mission_bridge 启动/重启的场景。`_write_and_start_mission()` 里若有生效值也补一次应用，保证任务执行前生效。
- `_cb_send_waypoints` 中：`request.max_speed > 0` 且非 NaN → 钳位到 `(0, max_speed_hard_cap]`，调 `_apply_max_speed` + `_persist_max_speed`；`<=0` → 保持现状不动。速度处理失败不影响航线下发本身（告警日志，响应按航线结果返回，message 附加速度应用结果）。
- 清除接口（沿用 `cancel_mission` 的双通道 house style）：
  - `std_srvs/srv/Trigger` 服务 `/mission_bridge/clear_max_speed`
  - 共用 `_apply_clear_max_speed()`：删持久化文件 + 把 `desired_linear_vel` 设回 `default_max_speed`，返回 success/message。

### 3. 参数文件：`mission_stack.real_boat.yaml`

`mission_bridge:` 块下新增：

```yaml
    # 平台下发最大速度的默认值（须与 nav2_params FollowPath.desired_linear_vel 一致）
    default_max_speed: 0.5
    # 与 ardupilot_velocity_bridge max_linear_x 对齐的硬顶
    max_speed_hard_cap: 1.1
```

- `docs/Nav2在线调参与ArduPilot对接说明.md`：更新"决策层 speed 字段目前未接入 Nav2"的描述，补一节说明本机制（下发→持久化→重启恢复→清除）。
- `docs/nav_task_interface.md` / `docs/decision_nav对接文档.md`：SendWaypoints 新字段说明。

### 5. 验证

1. `colcon build --packages-select m_common workspace_nav` 编译通过。
2. 本机烟测（无船）：
   - 起 `controller_server`（或 mock 同名节点带参数）+ mission_bridge；
   - `ros2 service call /mission_bridge/send_waypoints` 带 `max_speed: 0.8` → 确认 `FollowPath.desired_linear_vel` 变 0.8 且 `json/max_speed.json` 落盘；

## 修改最大速度对导航表现的影响（给平台的说明）

会影响，建议平台把速度限制在 **0.3 ~ 0.8 m/s** 区间，超出需重新水上调参：

- RPP 前瞻距离随速度缩放（`L ≈ v × lookahead_time(16s)`，钳位 [5, 8] m），速度变了转弯特性跟着变：提速后弯道过冲/画弧变大；降速后可能低于舵效下限（`regulated_linear_scaling_min_speed: 0.1` 注释已提示"过低舵效差易画圈"）。
- 碰撞检测弧长 = `v × max_allowed_time_to_collision(20s)`：提速后检查距离变长、误急停概率上升；降速则变短。
- 现有参数围绕 0.5 m/s 实测调好；1.1 m/s 是下游桥的安全硬顶，超过会被截断。
