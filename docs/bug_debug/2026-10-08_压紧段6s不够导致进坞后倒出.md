# 2026-10-08 压紧段 6s 窗口不够：明明已进坞仍判 FINAL_PUSH_TIMEOUT 倒车驶出

## 1. 基本信息

- 日期：2026-10-08 晚 18:29（归港节点重启后的第一次归港）
- 船 / 工作空间：兴飞 `ssh hkzl`（MEC-MB002），`~/usv-main`
- 数据来源：`~/logs/xingfei_stack/docking.log`、`~/logs/xingfei_stack/rs485.log`
- 相关参数：`final_push_time_sec`（FSM）、`io_wait_input_mask`（RS485 驱动，默认 `0x0003`）

## 2. 现象

船已经倒进坞里（目视到位），FSM 仍在 6 秒后报 `FINAL_PUSH_TIMEOUT -> ABORT_EXIT`，
主动倒车驶出坞外等重试。现场感受是"明明已经进来了，为啥归港还要出去"。

## 3. 证据

### 3.1 时间线（`docking.log`，时间戳 Unix 秒已换算）

```text
18:29:17.86  ALIGN_ENTRY -> BACK_IN
18:29:18.02  已发送 WaitIO（等待夹爪抓住/停泊到位检测）
18:29:21.56  BACK_IN -> FINAL_DOCK
18:29:23.96  FINAL_DOCK 到达死位置，进入压紧段（低速继续倒船，等待夹爪抓住）
18:29:29.86  坞内中止（FINAL_DOCK）: FINAL_PUSH_TIMEOUT -> ABORT_EXIT   ← 距进压紧段 5.9s
```

### 3.2 压紧段里的 DI 原始读数（`rs485.log`）

```text
18:29:24.6~29.2  IO query n/3000: input=0x0000
18:29:29.477     IO query 28/3000: input=0x0002   ← DI1 闭合（进压紧段后 5.5s）
18:29:29.771     IO query 29/3000: input=0x0002
18:29:30.065     IO query 30/3000: input=0x0002
18:29:30.360     IO query 31/3000: input=0x0002
18:29:30.520     WaitIO cancel request received   ← FSM 超时放弃并取消 WaitIO
```

**DI0 全程未置位**；WaitIO 成功判据是 `(input & 0x0003) == 0x0003`
（`usv_rs485_node.cpp:1126`），所以始终判不出"夹爪抓住"。

### 3.3 全天 DI 取值统计

```text
163 次 input=0x0000
  4 次 input=0x0002
  1 次 input=0x0003     ← 唯一一次，出现在 17:36:50
```

17:36:50 那次是 `WaitIO` 的**第 1 次查询**就直接 `0x0003`（Modbus 原始帧
`40 02 01 03`，DI 字节 0x01/0x03），当时船正坐在坞里。
→ **两个检测开关都能闭合，说明不是开关/接线坏了，而是压紧段的时间和深度不够。**

### 3.4 叠加因素：今天判据只剩一条

`docking_fsm.py` 文件头（2026-10-08 改）：

> 删除充电信号判据：rs485 驱动改版后 `/wireless_charger_state` 只在夹爪抓住后才发布，
> 充电判据不可能先于抓住触发，判定由 WaitIO 单一口径

即 `0x0003` 成了唯一的 DOCKED 判据，它不满足时无论船是否真的进坞，
都只有 `FINAL_PUSH_TIMEOUT -> ABORT_EXIT` 一条路。

## 4. 根因（已确证）

1. 成功判据 `io_wait_input_mask = 0x0003` 要求 DI0+DI1 同时置位；
2. 实船压紧过程中 DI1 在 **5.5s** 才闭合，DI0 更晚（本次 6s 内没到）；
3. `final_push_time_sec = 6.0` 太紧 → 必然在 DI 到位前超时；
4. 叠加判据只剩这一条 → 表现为"进坞了也判失败、倒车出去"。

## 5. 已做修改（2026-10-08 晚，待现场验证）

- `src/usv_docking/usv_docking/docking_fsm.py`：`final_push_time_sec` 默认值 `6.0 → 15.0`
- `src/usv_docking/config/docking.yaml`：同上（yaml 是运行期生效的那份）
- 船端：两份文件已同步 + `colcon build --packages-select usv_docking`；
  运行中的节点已在线设置并回读确认：

```text
ros2 param set /docking_fsm final_push_time_sec 15.0   → Set parameter successful
ros2 param get /docking_fsm final_push_time_sec       → Double value is: 15.0
```

- 单测：`usv_docking` 115 passed（另把 `test_final_push_timeout_aborts` 改成跟随参数，
  不再写死 6s，避免以后调参就失效）
