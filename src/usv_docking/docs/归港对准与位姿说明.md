# 归港对准与位姿说明

本文说明 **AprilTag 输出含义**、**y 与 yaw 是否重复**、**如何用双码判断「对准通道」**，以及与 VRX 类 GNC 思路的对应关系。  
控制实现见 `docking_controller.py`；完整状态机见 [`docs/usv_docking任务规划.md`](../../../docs/usv_docking任务规划.md)。

---

## 1. 输出到底是什么？

### 1.1 `/apriltag_node/dock_pose`（相机系）

```text
Float64MultiArray [x, y, z, roll, pitch, yaw]
frame_id = camera_rear_link（仿真）/ camera_left_link（实船）
```

语义：**bay 中心 P（船坞通道中心）在相机坐标系下的位姿**——不是单个二维码中心，也不是 world/odom 坐标。

```text
Tag 检测位姿  ×  dock_offset（Tag 系：码中心 → bay 中心 P）
    → 发布 dock_pose（bay 中心在 camera_*_link 下）
```

双码（id 0 / 43）同时可见时，`apriltag_localization` 对多路结果 **取平均** 后再发布；单码与双码的 y 可能略有差别，属正常现象（见 §5）。

### 1.2 `/dock/status` 里的 `x_base / y_base / yaw_base`（船体系）

`usv_docking` **不直接用** `dock_pose` 的相机系 x/y 控船，而是：

```text
dock_pose（camera_frame）
    → TF：camera_frame → base_link
    → EMA 滤波
    → x_base, y_base, yaw_base
    → heading_error = wrap(yaw_base - heading_offset_rad)
```

| 量 | 含义（base_link） | 归港主要用途 |
|----|-------------------|--------------|
| `x_base` | bay 中心沿船体 **前后轴** 的距离 | 倒船深度、到位停车 |
| `y_base` | bay 中心相对通道中心线的 **横向偏差** | **对准判据**、弧线纠偏 |
| `yaw_base` | bay 姿态在 base_link 下的 **原始 yaw**（TF 后） | 诊断；后向相机 spawn 对准时常 **≈ π** |
| **`heading_error`** | 倒船入泊用的 **航向误差** | **PRE_ALIGN / GATE / BACK_IN 门槛与控制** |

**后向相机 + 倒船**：spawn 船尾朝码头且已对准通道时，几何上 **`yaw_base ≈ π` 才是「已对准」**，不是 0。仿真 yaml 设 **`heading_offset_rad: π`**，使 **`heading_error ≈ 0`**。若用原始 `yaw_base` 做 PRE_ALIGN，会误判为差 180° 而 **原地转圈直到 Tag 出视野**。

**结论**：对准判据与控制看 **`y_base` + `heading_error`**（或等价地 `yaw_base` 减 π）；不要在大 |yaw_base|≈π 时当作未对准。

## 2. y 和 yaw 像不像？要不要两个都卡？

**不像，也不能只盯一个。** 它们是同一刚体位姿里 **两个独立的误差分量**。

### 2.1 几何直观（俯视图，倒船接近码头）

```text
通道中心线 ↑

     |    · P（bay 中心，目标在原点）
     |   /
     |  /  ← 仅 yaw 偏：船尾指向斜的，人可能在中心线上
     | /
     |/____ 船（base_link）
     
     · P
        \
         \____ 船   ← 仅 y 偏：船平行于通道但偏在左侧

     · P
       \  \
        \  \____ 船  ← y 和 yaw 都偏：最常见
```

| 误差 | 物理含义 | 只修另一个能否解决 |
|------|----------|-------------------|
| **y_base** | 横向「偏左/偏右」 | 光修 yaw **不能**消除 y（差速船 v=0 无侧移） |
| **yaw_base** | 船头/船尾与通道夹角 | 光修 y（弧线）可顺带减 yaw，但 **PRE_ALIGN 阶段需单独修 yaw** |

远距离时，**大 yaw 会在相机系里投影成很大的 x/y 变化**（看起来像 y 乱跳），所以流程上：

1. **PRE_ALIGN**：先压 **|yaw_base|**（v=0 只转）  
2. **OUTSIDE_CENTERING**：再用弧线同时修 **y + yaw**  
3. **GATE_CHECK**：**|y| 与 |yaw| 同时** 小于门槛才进通道  

这与 VRX / 海洋 GNC 里常见的 **cross-track error（横向）+ heading error（航向）分开处理** 一致，并不是重复条件。

### 2.2 为何必须「两个都小」才允许 BACK_IN？

窄通道里：

- **只有 y 小、yaw 大** → 倒船时会 **斜着进通道**，一侧先撞浮块  
- **只有 yaw 小、y 大** → 整条船在通道 **偏一侧**，BACK_IN 微调不够  

因此本包 `gate_ready` 定义为 **同时** 满足（见 `docking_controller.py`）：

```text
|y_base|   < corridor_enter_y_limit
|yaw_base| < corridor_enter_yaw_limit
```

并连续 `gate_ready_cycles` 帧为真，才进入 `DOCK_BACK_IN`。

仿真默认（`docking_controller_sim.yaml`）：

| 参数 | 默认 | 约等于 |
|------|------|--------|
| `corridor_enter_y_limit` | 0.35 m | 横向 ±35 cm 内 |
| `corridor_enter_yaw_limit` | 0.15 rad | 航向 ±8.6° 内 |
| `gate_ready_cycles` | 5 | 连续 5 帧（20 Hz 约 0.25 s） |

实船通道更窄时可收紧（见 `docking_controller_real.yaml`）。

## 3. 双码（Tag 0 + 43）与「对准」关系

### 3.1 双码的作用

- 左右各一码，经 `dock_offset` 都指向 **同一 bay 中心 P**  
- 双码可见 → 位姿平均，**降噪**  
- 单码可见 → 仍可输出（仅一侧 placard）

### 3.2 对准看哪里？

**不要**用原始 `dock_pose` 的 y 在相机系里判断对准；**不要**在大 |yaw| 时信相机系 y。

**看 `/dock/status`：**

```bash
ros2 topic echo /dock/status
# 关注：y_base, yaw_base, gate_ready, gate_ready_count
```

对准双码 / 对准通道的实用标准：

```text
gate_ready == true
且 state 即将 / 已经 DOCK_GATE_CHECK → DOCK_BACK_IN
```

手动联调时可记：

```text
|y_base|   < 0.35 m（可调）
|yaw_base| < 0.15 rad（可调）
```

### 3.3 单码 y 对、双码 y 不对

常见原因：

1. 两 Tag 的 `dock_offset_y` 未 **分别** 单码标定好 → 平均 y 被拉偏  
2. 双码同屏时 AprilTag 检测与单码时略有差异 → 平均与单码不一致  

**建议**：

- 标定阶段：`tag_ids: [0]` / `[43]` 分别调 `dock_offset_y`  
- 运行阶段：若双码 y 仍不稳，可 **归港只用一侧** `tag_ids: [43]` 或 `[0]`  
- 控制仍用 **y_base + yaw_base 双门槛**，与单双码无关

## 4. 与参考项目 [Nzwili/asv-autonomous-docking-and-path-tracking](https://github.com/Nzwili/asv-autonomous-docking-and-path-tracking) 的对比

该仓库（VRX / WAM-V）特点：

| 项 | 参考项目 | 本仓库 `usv_docking` |
|----|----------|----------------------|
| 栈 | MATLAB/Simulink + ROS 2 + Gazebo VRX | ROS 2 Python + Gazebo + AprilTag |
| 公开代码 | 以 `.mlx` / Simulink 为主；`vrx_world/` 主要为 **sydney_regatta.sdf** | 完整 Python 状态机 + yaml |
| 感知 | 文档描述为 GNC 制导（具体 Tag 接口在 zip 内） | **AprilTag → dock_pose → TF → base** |
| 对准思路 | 经典 **横向误差 + 航向误差** 分阶段制导、路径跟踪再入泊 | **PRE_ALIGN（yaw）→ OUTSIDE（y+yaw 弧线）→ GATE（双阈值）→ BACK_IN** |

**可借鉴的理念（已实现或对齐）：**

1. **分阶段**：先对齐航向，再在通道外修横向，最后直线入泊 —— 对应 `DOCK_PRE_ALIGN` / `OUTSIDE_CENTERING` / `BACK_IN`  
2. **双误差判据**：横向 + 航向同时进门槛 —— 对应 `gate_ready` 的 y **与** yaw  
3. **VRX 世界**：参考库 `vrx_world` 与本地 `sydney_regatta.sdf` 同类；本工程默认 **`dock_2022` + 双 placard**，需单独 AprilTag 标定  

**不宜直接照搬：**

- 其 MATLAB 控制增益、WAM-V 动力学与 **RoboBoat 差速倒船** 不同，yaml 需在本仿真/实船重调  
- 公开 GitHub **无** 可直接复用的 ROS 2 docking 节点，仅世界文件与 Simulink 包可参考流程

## 5. 联调检查清单

| 步骤 | 操作 | 期望 |
|------|------|------|
| 1 | 船在通道中心，只开 tag0 | `y_base`、`yaw_base` 接近 0 |
| 2 | 只开 tag43 | 同上（分别调 `dock_offset_y`） |
| 3 | 双码 | `y_base` 与单码接近，勿差几十厘米级 |
| 4 | `/dock/start` 后看 `gate_ready` | 入泊前应为 true 且连续计数增加 |
| 5 | 故意偏航 / 偏横 | `gate_ready` 变 false，不应进 `BACK_IN` |

## 6. 相关参数速查

| 参数 | 作用 |
|------|------|
| `prealign_yaw_limit` | PRE_ALIGN 结束：\|yaw\| 小于此值 |
| `corridor_enter_y_limit` | GATE：\|y\| 门槛 |
| `corridor_enter_yaw_limit` | GATE：\|yaw\| 门槛 |
| `back_in_y_limit` / `back_in_yaw_limit` | 通道内超限 → ABORT |
| `ky_out` / `kyaw_out` | 码头外弧线修 y、yaw 增益 |
| `pose_filter_alpha` | 位姿 EMA，过大易 lag，过小易抖 |

完整列表：`config/docking_controller_sim.yaml`。
