# 导航与归港（Docking）异常告警文档

> 适用栈：`/home/ght/wuxihik_navigation`
> 覆盖：Nav2 导航（`mission_bridge` + `nav_status_aggregator`）与归港（`dock_mission` + `usv_docking` V2）
> 用途：作为上云/地面站对接的告警清单、订阅字段参考与处置手册

---

## 1. 范围与阅读前提

- 本文档只列**导航 + 归港侧真实可上报**的告警，不包含 AI 识别（排河口/违钓）、水质、电池/推进器等设备级故障（这些由感知/设备/控制侧上报）。
- 所有字段以 ROS 2 Humble 实际消息定义为准。**Humble 的 `FollowWaypoints.Result` 没有 `error_code` 字段**（恒为 0），因此「规划失败 / 控制失败 / 受困」无法靠任务结果精细区分，需用持续状态通道（`/nav_status`、`/task_event`）。

---

## 2. 告警通道总览（平台订阅表）

| 话题 | 类型 | 频率 | 生产节点 | 用途 |
|---|---|---|---|---|
| `/nav_status` | `m_common/msg/NavStatus` | 2 Hz | `nav_status_aggregator` | 导航持续状态/告警布尔（受困、定位、规划、任务态） |
| `/task_event` | `std_msgs/String`（JSON） | 事件 | `nav_status_aggregator` | 任务生命周期 + 报警 `ALARM_RAISED/CLEARED` |
| `/mission_bridge/status_detail` | `std_msgs/String`（JSON） | 事件 | `mission_bridge` | 任务明细（供 aggregator 消费） |
| `/dock/status` | `std_msgs/String`（JSON） | 事件 | `docking_fsm_v2` | 归港 V2 唯一上层契约（状态/中止原因/重接近/人工接管） |
| `/dock_task/event` | `std_msgs/String`（JSON） | 事件 | `dock_mission_node` | 归港任务事件（`DOCK_FAILED`、`MANUAL_TAKEOVER_REQUESTED` 等） |
| `/dock_task/status` | `std_msgs/String`（JSON） | 状态 | `dock_mission_node` | 归港任务状态快照 |

> 归港侧任务结果码另有 `m_common/action/NavigateTask` 的 Result 字段，但那是**导航**任务（去预泊点）的结果；归港本体结果走 `/dock_task/event`。

---

## 3. 二级分类总表

### 一级 A：导航运行异常

| 二级告警 | 实际代码 | 级别 | 通道 | 触发条件 | 状态 |
|---|---|---|---|---|---|
| 路径规划失败 | `PLAN_FAILED` | WARN | `/nav_status.planner_last_error`、`/task_event ALARM_RAISED` | planner action `ABORTED`（BT 内实时，任务仍在 RUNNING 也能抓） | ✅ |
| 导航控制/船体受困 | `CTRL_STUCK` | ERROR | `/nav_status.controller_status=STUCK`、`controller_last_error`、`/task_event` | 任务 RUNNING 期间 odom 位移在 `stuck_progress_timeout`(12s) 内 <0.3 m | ✅（**控制 + 受困合并为一码**） |
| 定位等级下降 | `LOC_DEGRADED` | WARN | `/nav_status.localization_overall=DEGRADED` | 定位协方差/GPS 等级退化 | ✅ |
| 定位丢失 | `LOC_LOST` | ERROR | `/nav_status.localization_overall=LOST` | TF 不可用或位置协方差超阈值 | ✅ |
| 任务失败（兜底） | `MISSION_FAILED` | — | `/nav_status.last_error` | 任务整体非 SUCCEEDED，无法归类为其他码时 | ✅ |
| 任务冲突 | `NavigateTask Goal REJECT`（不产 Result） | — | 任务被拒 | RUNNING/PAUSED/已激活时又来新任务 | ✅ |
| 任务数据非法 | `NavigateTask Goal REJECT`（不产 Result） | — | 任务被拒 | 航点空、经纬度非有限值、(0,0)、越界、违反作业区/禁航区 | ✅ |
| 任务执行超时 | 无 | — | — | 系统无「任务总时长超时」逻辑 | ❌ |
| 遥控/平台接管 | 无 | — | — | `NavStatus.flags_manual_override` 硬编码 `false`，导航栈不产 | ❌ |

### 一级 B：归港（船坞对接）异常

| 二级告警 | 实际代码/原因 | 级别 | 通道 | 触发条件 | 处置 |
|---|---|---|---|---|---|
| 去预泊点导航失败 | `DOCK_STAGING_NAV_FAILED` | WARN | `/dock_task/event` | NAV_TO_STAGING 期间 Nav2 `TASK_FAILED` | 自动重试（`staging_retry`） |
| 预泊重试耗尽 | `MANUAL_TAKEOVER_REQUESTED` / `needs_manual_takeover` | ERROR | `/dock_task/event` | 重试次数 ≥ `retry_max` | 人工接管 |
| 入口校验不合格 | `DOCK_INVALID_ENTRY`，子因见下表 | WARN | `/dock_task/event` | ENTRY_VALIDATE 拒绝 | 重规划预泊 / 退回 |
| 入泊控制失败 | `DOCK_CONTROLLER_FAILED`，`abort_reason` 见下表 | ERROR | `/dock/status` | V2 各阶段超时/丢 Tag/走廊违规 | 坞内自动驶离，坞外上报 |
| 坞内失败自动驶离 | `ABORT_EXIT`（`v2_state`） | — | `/dock/status` | 走廊内（BACK_IN/FINAL_DOCK）失败 | 沿轴线驶出后回 IDLE |
| 入泊未到位需重新接近 | `needs_reapproach=true` | — | `/dock/status` | 入泊失败且可重试 | dock_mission 重导航预泊后再 `/dock/start` |
| 出泊失败 | `UNDOCK_TIMEOUT` / 出泊期 `DOCK_ABORT` | ERROR | `/dock/status` | MONITOR_UNDOCK 超时或状态回 `DOCK_ABORT` | 上报失败 |
| 入泊后充电确认超时 | `DOCK_CHARGE_TIMEOUT` | WARN | `/dock_task/event` | 入泊后 `is_charging` 在 `charge_stale_sec` 内未确认 | 上报，需人工确认 |
| 安全硬停 | `safety_stop` + `SAFETY:ODOM_*`/`TOPIC_TIMEOUT` | ERROR | `/dock/status.abort_reason` | odom 真异常 / 上游节点断流 | **不可盲驶，直接 FAILED 停车 + 人工接管** |

#### 归港入口校验子因（`/dock_task/event` detail）

| 子因 | 含义 |
|---|---|
| `EX_BEYOND_ENTRY` | 船相对坞入口位置超出 |
| `EX_TOO_DEEP` | 进入过深 |
| `EY_TOO_LARGE` | 横向偏差过大 |
| `EYAW_TOO_LARGE` | 艏向偏差过大 |
| `RTK_NOT_FIX` | RTK 未固定解 |
| `FRAME_MISMATCH` | 坐标系不匹配 |
| `TAG_NOT_VISIBLE` | 未识别到船坞 Tag |
| `POSE_UNAVAILABLE` | 位姿无效 |

#### 归港入泊控制失败子因（`/dock/status.abort_reason`）

| 子因 | 含义 |
|---|---|
| `ACQUIRE_TIMEOUT` | 搜 Tag 超时（60s） |
| `APPROACH_TIMEOUT` | 接近入口超时（90s） |
| `ALIGN_TIMEOUT` | 对准超时（45s） |
| `REACQUIRE_TIMEOUT` | 重搜 Tag 超时（30s） |
| `BACK_IN_TIMEOUT` | 坞内后退超时（90s） |
| `FINAL_DOCK_TIMEOUT` | 终坞超时（60s） |
| `TAG_LOST_IN_BACK_IN` | 后退中丢 Tag |
| `TAG_LOST_IN_FINAL_DOCK` | 终坞丢 Tag（2s） |
| `CORRIDOR_VIOLATION` | 走廊违规（连续 violation） |
| `GLOBAL_TIMEOUT` | 单次任务总超时（150s） |
| `SAFETY:LATERAL_ERROR` 等 | 安全节点软停/硬停原因 |

### 一级 C：设备/传感异常（栈内能判的部分）

| 二级告警 | 实际判据 | 状态 |
|---|---|---|
| RTK/GNSS 离线 | `localization_gps_fix`、`alerts_gps_stale`、归港 `RTK_NOT_FIX` | ⚠️ 部分（定位侧能反映 GPS 掉/质量差） |
| IMU/odom 断流 | `alerts_odom_stale`、归港 `TOPIC_TIMEOUT(ODOM)` | ⚠️ 部分 |
| 船控离线 | `safety_stop` / 上游话题断流 `TOPIC_TIMEOUT` | ⚠️ 部分 |
| 摄像头/激光雷达/水质/电池/推进器离线 | 导航+归港栈不直接产；视觉丢失近似 `tag_visible=false` / `pose_source` | ❌ 需感知/设备侧 |

| 字段 | 取值 | 说明 |

| `last_error` | 空/`CTRL_STUCK`/`PLAN_FAILED`/`LOC_LOST`/`LOC_DEGRADED`/`MISSION_FAILED`/`EMERGENCY_STOP` | 错误码 |

| `controller_status`/`controller_last_error` | `OK`/`STUCK`；`CTRL_STUCK` | 控制器/受困 |
| `localization_overall` | `GOOD`/`DEGRADED`/`LOST` | 定位 |
| 告警布尔 | `alerts_odom_stale`、`alerts_gps_stale`、`alerts_mission_bridge_alive`、`alerts_planner_error`、`alerts_controller_error`、`alerts_emergency_active`、`alerts_mission_paused`、`flags_recovery_active`、`flags_emergency_stop` | 组合判断用 |

| 字段 | 取值 | 说明 |
|---|---|---|

## 6. 已知限制（对接时务必说明）

1. **Humble 无 Nav2 原生错误码**：`FollowWaypoints.Result` 只有 `missed_waypoints[]`，`ComputePathToPose.Result` 只有 `path`+`planning_time`。因此导航失败**不输出**「目标在障碍物里 / 路径不可行 / 起点异常 / TF 缺失」这类细粒度原因码，只有 `PLAN_FAILED` 这一层。
2. **受困不是任务结果码**：`NavigateTask.Result.RESULT_STUCK(7)` 定义了但当前代码从不返回；受困只能从 `/nav_status`、`CTRL_STUCK` 报警读取。整段导航失败基本落 `RESULT_INTERNAL_ERROR(99)`。
3. **`_map_nav2_failure` 在 Humble 下失效**：它按 `nav2_error_msg` 关键字区分 `PLANNING_FAILED/CONTROLLER_FAILED`，但 Humble 该字段恒为空，故整体失败归 `INTERNAL_ERROR`；仅「单点 missed」路径会给 `RESULT_PLANNING_FAILED(5)`。
4. **控制失败与受困合并**：`controller_status` 只有 `OK`/`STUCK`，无独立「控制失败」状态；要拆开需在导航侧增加跟踪误差/控制指令丢失判据。
5. **`CTRL_STUCK` 生效前提**：`enable_mission_bridge:=true`（才有 `nav_status_aggregator` 节点）+ odom `/mavros/gps_input/local` 正常 + 任务处于 RUNNING。
6. **归港 `TAG_NOT_VISIBLE` 不等同「AI 识别告警」**：它只表示 dock V2 视觉在归港阶段未看到 Tag；排河口/违钓等 AI 识别告警不在本栈。

## 7. 推荐对接口径（一句话版）

> 导航侧可报：`PLAN_FAILED`、`CTRL_STUCK`（控制+受困合并）、`LOC_LOST`、`LOC_DEGRADED`、`MISSION_FAILED`，通道 `/nav_status`、`/task_event`。归港侧可报：去预泊导航失败、入口校验不合格（未识别到船坞/对准/进坞失败）、入泊控制失败（各阶段超时、丢 Tag、走廊违规）、坞内自动撤离、出泊失败、充电超时、重试耗尽需人工接管，通道 `/dock/status`、`/dock_task/event`。**暂不提供**：任务执行超时、遥控/平台接管、以及推进器/激光雷达/摄像头/水质/电池等设备级离线（属设备或感知侧）。

## 8. 附录：归港状态机流转（快速定位）

```
IDLE ──(DOCK_TASK_ACCEPTED)──► NAV_TO_STAGING ──(TASK_COMPLETED)──► SETTLE
   └─(TASK_FAILED)─► 重试/耗尽 ──► MANUAL_TAKEOVER_REQUESTED / DOCK_FAILED
SETTLE ──► ENTRY_VALIDATE ──(OK)──► DOCK_HANDOFF ──► MONITOR_DOCK
   └─(EntryReason 拒)─► 重规划/退回
MONITOR_DOCK ──(success)──► COMPLETE_SETTLE ──► SUCCEEDED
   └─(needs_reapproach)─► 重试
   └─(DOCK_ABORT / DOCK_CONTROLLER_FAILED)─► ABORT_EXIT 驶出 ──► FAILED
UNDOCK：UNDOCK_HANDOFF ──► MONITOR_UNDOCK ──(undock_success)──► COMPLETE_SETTLE
   └─(UNDOCK_TIMEOUT / DOCK_ABORT)─► FAILED
```

> 关键文件：`nav_status_aggregator.py`、`mission_bridge.py`、`dock_mission_node.py`、`docking_fsm_v2.py`、`docking_safety_v2.py`。
