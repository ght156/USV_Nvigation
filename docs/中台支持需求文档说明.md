## 1. 背景与目标

### 1.1 项目背景

- 按《算法组研发与测试计划_20260813》，P0＝2026-10-31 前交付首船，P1＝2026-12-31 前完成第二批，P2 另行排期；
- 需要中台在以下方向支持：
  1. VLM 语义识别预研（qwen-vl + 提示词优化）；
  2. 检测结果地理化（像素框 → 3D 位置）；
  3. 智能清扫执行（smart_clean，支持 YOLO 与 VLM 双识别源）；
  4. 避障相关优化（动态障碍代价时间衰减等）。

### 1.2 总体分工

| 模块 | 负责方 | 说明 |
| --- | --- | --- |
| YOLO 垃圾检测基线（4 类） | 算法组/中台 | 算法组目前识别仅有塑料瓶，需要额外类型支持 |
| VLM 语义识别预研 | 中台 | 基于 YOLO 候选框，qwen-vl + 提示词优化 |
| 检测结果地理化（像素框→3D 位置） | 中台实现，算法组提供标定数据与验收支持 | 相机内参/外参、云台角度、水面投影 |
| 智能清扫执行（smart_clean） | 中台 | 算法组提供导航代码与接口，中台实现插队/清扫/恢复 |
| 避障 P0/P1（仅激光雷达） | 算法组 | 中台支持“动态障碍代价时间衰减”优化 |
| 人员/动物保护（P2 预留） | 中台（预留） | 复用统一检测接口，后续单独立项 |

### 1.3 支持周期与优先级

- 与研发计划口径一致：P0＝2026-10-31 前完成，P1＝2026-12-31 前完成，P2 另行排期；
- 各任务优先级见 §2，阶段划分见 §5.4。

## 2. 中台支持任务清单

### 任务 1：VLM 语义识别预研（P1）

**目标**

- 以 YOLO 检测结果为候选框来源，评估并实现 qwen-vl + 提示词优化方案；
- 回答工程问题：推理端（船端 AGX/NX 或服务端）、帧率、单帧时延、量化方案、提示词鲁棒性；
- VLM 不上船，保留为预研技术储备。

**范围**

- 输入：原图 + YOLO 候选框（坐标或裁剪图）+ 任务提示词；
- 输出：每框判定（接受/拒绝、类别、置信度）或结构化场景描述；
- 开放词汇能力：识别类别不限于 YOLO 固定 4 类（塑料瓶/塑料袋/泡沫/树叶），可覆盖“白色垃圾”等语义描述；
- 检测结果地理化由任务 2 负责，VLM 模块本身不做 3D 估计。

**接口约定**

- 与算法组 YOLO 解耦：中台预研期可自行准备候选源占位，但交付物必须是“图 + 候选框 + 提示词 → 判定”模块；
- 提供方式建议为 service（如 `/vlm_classify`）：请求携带图像时间戳与候选框，响应返回每框判定；若部署在服务端，需明确网络时延、超时与降级策略（不可阻塞实时导航循环）。（具体方式可自定）

**交付物**

1. VLM 模块源码（含提示词模板与配置文件）；
2. 预研报告：推理端选型、帧率/时延/量化实测数据、提示词鲁棒性分析、上船/不上船建议；
3. 评测结果：在双方约定的独立测试集上的指标；
4. 接口文档（含调用示例）。

**验收口径**

- 对 YOLO 候选框的正确过滤/纠错能力（误接受率、漏接受率）以双方约定的测试集为准；
- 开放词汇类别识别可用性：对指定语义描述可正确判定；
- 端到端时延与资源占用给出可复现的实测数据。

### 任务 2：检测结果地理化（像素框 → 3D 位置）（P1）

**目标**

- 将 YOLO/VLM 输出的像素框转换为水面 3D 位置，统一发布为归一化检测结果；
- 输出两级位置：map 系位置（导航航点用）与 base_link 系相对位置（近距对准用）。

**范围**

- 输入：YOLO/VLM 像素框（含图像时间戳）、相机内参/外参、云台角度、船姿态、水面高度假设；
- 处理：框反投影到水面 → 转换到 base_link 系 → 结合 RTK/航向转换到 map 系；
- 输出：`/garbage_detection`（DetectionObjList，header.frame_id=map，含 base_link 相对位置字段）；
- 时间戳对齐与过期处理：VLM 延迟结果不得污染实时输出。

**交付物**

1. 地理化节点源码（接入算法组导航栈）；
2. 相机标定与投影参数配置文档；
3. 投影误差分析报告（不同距离下的实测误差）。

**验收口径**

- 10m 内水面投影位置误差 ≤0.5m（目标值，实测后冻结）；
- 实时输出频率跟随 YOLO 检测（≥5Hz）；近距相对位置随 YOLO 帧率更新；
- 输入缺失（无姿态/无标定）时明确标记无效，不静默输出。

**依赖与支持**

- 算法组提供：相机标定数据（内参/外参）、云台角度接口说明、地图基准（ref_gnss_10）、RTK/航向话题说明；
- 算法组参与联调与误差验证。

### 任务 3：智能清扫执行 smart_clean（P1）

**目标**

- 在算法组提供的导航代码基础上，实现智能清扫模式：上层下发航点任务后，任务途中检测到垃圾则插队去清扫，完成后恢复原任务，直到到达最终航点；
- **同时支持 YOLO 与 VLM 两种识别源**（任一源可用即可触发；VLM 不作为实时控制闭环依赖）。

**范围**

- 插队与恢复状态机：保存剩余航点与当前索引 → 插队去垃圾点 → 清扫动作 → 恢复剩余航点；
- 去重与冷却：track_id 去重、同一位置冷却时间，防止反复追同一个垃圾；
- 兜底规则：目标不可达/越界/低置信度消失 → 放弃插队继续原任务；单次任务插队次数上限；过期检测忽略；
- 状态上报；
- 清扫完成判定：默认 V1 采用“到达垃圾点后低速通过覆盖收集口宽度 + 复检（YOLO 无目标）或计时”判定，最终口径待冻结。

**行为契约（smart_clean）**

```
平台切换智能清扫模式
  → 上层下发航点任务（SendWaypoints）
  → 任务途中收到 /garbage_detection（置信度≥阈值、类别在允许集、位置在围栏内）
  → 保存剩余航点与当前索引
  → 插队：将垃圾点作为下一目标执行
  → 到达后执行清扫动作（低速 + 收集机构接口，由嵌软提供；无机构时以低速通过占位）
  → 清扫完成（复检/计时/嵌软信号）
  → 恢复剩余航点继续执行
  → 到达最终航点 → 任务完成
```

**安全红线（硬性要求，中台不得修改）**

- `mission_bridge` 的 EMERGENCY 语义：进入急停后必须人工取消才能恢复，不自动恢复；
- 电子围栏（SAFE-001）强制不穿越；
- 新任务覆盖规则（运行中不接受覆盖）与急停优先级；
- 中台只能新增节点/模块，通过现有 service 交互，不允许改动 mission_bridge 核心逻辑。

**交付物**

1. smart_clean 节点源码（独立模块，接入算法组导航栈）；
2. 仿真联调环境（基于 mock 检测源 + RViz/Nav2 仿真）；
3. 行为说明文档与测试用例（插队/恢复/去重/兜底/双源切换）；
4. 接口联调记录。

**验收口径（仿真先行，实船后补）**

- 单次垃圾插队：插队、清扫、恢复、最终到达原航点全流程通过；
- 双源：YOLO-only、VLM-only（mock）、双源三种模式均可触发并正确执行；
- 兜底：目标越界/低置信度消失/连续多次插队达到上限时，正确放弃并继续原任务；
- 安全：急停/取消/暂停任一时刻介入，任务状态机行为正确；
- 实船口径：按《算法组研发与测试计划》PER-009 待核定口径执行。

### 任务 4：动态障碍代价时间衰减（P0）

**目标**

- 解决 Nav2 VoxelLayer 动态物 ghost 残留问题：当前代价只靠射线/船体移动清除，不会按时间衰减；
- 降低水面动态物（漂浮物、船只、人员）离开后残留代价导致的误停车，支撑 PER-001“误停车≤2次/小时”验收。

**范围与方案**

- 方案 A（推荐）：集成 STVL（spatio_temporal_voxel_layer）替代 local voxel_layer，配置 `decay_time` 等参数；
- 方案 B：基于本地 nav2_ws 源码（humble 分支）自研/修改 VoxelLayer，增加按格时间戳衰减；
- 方案 C（临时兜底，不推荐长期）：周期性/卡住时调用 clear_costmap 服务；
- 集成后需与算法组确认 footprint、膨胀层参数联动，不影响静态/围栏代价。

**交付物**

1. 集成代码与参数配置（含与现有 nav2_params_real_mavros.yaml 的差异说明）；
2. 动态障碍场景测试记录（目标离开后代价清除时间、误停车前后对比）。

**验收口径**

- 动态目标离开视野/区域后，代价在设定时间内清除（目标值 ≤3s，待实测确认）；
- 静态障碍与电子围栏代价不受影响；
- 对水面波纹/杂波误报不劣于现状。

## 3. 接口契约

### 3.1 统一检测接口（YOLO/VLM 双源归一化）

**核心原则：模型只输出图框；位置由船端地理化节点计算（任务 2）。**

```
YOLO（船端，实时） ──► 候选检测（图框+类别+置信度+source+图像时间戳）
VLM（船端/服务端） ──► 候选检测（同上，开放词汇）
          │
          ▼
地理化节点（任务 2，中台实现：相机外参/云台角度/水面投影）
          │
          ▼
/garbage_detection（DetectionObjList，header.frame_id = map）
          │
          ▼
smart_clean（任务 3：插队/清扫/恢复）＋ 平台展示
```

**话题与消息**

| 话题 | 类型 | 说明 |
| --- | --- | --- |
| `/detection/yolo` | DetectionObjList | YOLO 原始检测（图框） |
| `/detection/vlm`（或 `/vlm_classify` service） | DetectionObjList / srv | VLM 检测结果（开放词汇） |
| `/garbage_detection` | DetectionObjList | 归一化结果，map 系，由地理化节点（任务 2）发布 |

**DetectionObj 字段约定（现有消息扩展建议）**

| 字段 | 说明 |
| --- | --- |
| `source` | 现有 SOURCE_UNKNOWN=0 / SOURCE_OBJECT=1 / SOURCE_APRILTAG=2，建议新增 SOURCE_VLM=3 |
| `label_name / class_id` | 类别；VLM 开放词汇可输出语义类别 |
| `confidence` | 置信度；YOLO 与 VLM 各自独立阈值，参数可配置 |
| `track_id` | 多目标跟踪 ID，用于去重 |
| `has_bbox / bbox_*` | 图像框（像素） |
| `has_pose / pose` | map 系位置（导航用），由地理化节点填充 |
| `relative_pose`（建议新增） | base_link 系相对位置（近距对准用），可选字段，向后兼容 |
| `header.stamp` | 检测时间戳；VLM 延迟结果必须用时间戳做过期判断 |

**配置项（平台可配）**

- 识别源开关：YOLO / VLM / both；
- 每源置信度阈值、类别白名单（不写死 4 类，VLM 开放词汇）；
- 同一目标冷却时间、单任务插队次数上限。

### 3.2 坐标系与投影约定

- YOLO/VLM 输出像素框，不做 3D 估计；
- 地理化节点（任务 2）负责：相机内参/外参、云台角度、船姿态、水面高度假设 → 框反投影为水面点；
- 输出两级位置：map 系点（导航航点）、base_link 系相对位置（近距对准）；
- 收集框系由 TF 提供（静态或随导流翼摆臂动态），谁需要谁转换，接口不直接传收集框坐标；
- 近距对准（最后 3~5m）只用 YOLO 实时结果，不用 VLM（秒级延迟不可进控制闭环）；
- 算法组提供相机标定数据、云台角度接口与地图基准，供地理化节点使用。

### 3.3 智能清扫相关服务/话题（后续可能会改）

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `/mission_bridge/send_waypoints` | m_common/srv/SendWaypoints | 下发航点任务（单点=1 个，多点=≥2 个） |
| `/mission_bridge/set_pause` | m_common/srv/SetPause | 暂停/继续 |
| `/mission_bridge/emergency_stop` | m_common/srv/EmergencyStop | 急停 |
| `/mission_bridge/cancel_mission` | m_common/srv/CancelMission | 取消/退出急停 |
| `/nav_status` | std_msgs/String（JSON） | 周期状态快照（约 2Hz） |
| `/task_event` | std_msgs/String（JSON） | 事件与告警 |
| Nav2 FollowWaypoints | nav2_msgs/action | 底层航点执行 |

## 6. 待确认事项（评审时冻结）

1. VLM 不上船；
2. smart_clean 清扫完成判定口径：复检 / 计时 / 嵌软信号（默认 V1 复检+计时）；
3. 近距对准（收集框系）是否纳入 V1（影响导入成功率≥90% 达成路径）；
4. 类别白名单与每源置信度阈值初始值；
5. 地理化精度验收口径：10m 内投影位置误差目标值（暂定 ≤0.5m，实测后冻结）；
6. 数据提供范围与标注分工（训练样例 vs 独立验收集）；
7. mock 检测源与仿真环境的分工（算法组提供脚本，中台搭建环境）。
